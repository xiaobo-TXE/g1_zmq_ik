# g1_zmq_ik

G1 双臂：**给一个目标位置 → ZMQ 读当前关节角 → 正解出当前末端位姿 → 反解出期望关节角 → ZMQ 下发**。

正解/反解用的是宇树 `xr_teleoperate` 的方案：`pinocchio` 加载 URDF + 符号运动学 + `CasADi Opti/IPOPT`
求解（权重 50 : 1 : 0 : 0.1，关节限位为硬约束）。源码逐行对照见 [`docs/对照宇树源码.md`](docs/对照宇树源码.md)。

依赖用 **uv** 安装（`pin` + `casadi` 都在 PyPI 上，不需要 conda）。

---

## 1. 工作流程

```
 ① 目标位置（默认 torso_link 系；x前 y左 z上，单位 m）
      │   来源：命令行 --pos / 交互输入 p x y z / 内置轨迹 --demo circle
      │        / ZMQ 6003 端口持续推送（外部程序可以随时一直下发，最新优先）
      ▼
 ② ZMQ 6001 订阅 LowState（机器人 PUB，约 500Hz）
      │   motor_state[15..28].q  →  14 维手臂关节角 q_meas
      │   motor_state[12..14].q  →  3 维腰关节角（供 ④ 做坐标换算）
      ▼
 ③ 正解 FK(q_meas)  ─────────────▶  当前末端位姿（日志里的 meas=）
      │   与反解共用同一个 CasADi 符号模型（内置正解，或 pinocchio.casadi）
      ▼
 ④ 目标换算：目标系 ──▶ 求解坐标系（locked 系）
      │   torso 系（默认）：常量平移 C = torso 原点相对 pelvis 44.18mm，**与腰角无关**
      │   pelvis 系       ：用实测腰角做刚体换算（含腰角旋转）
      ▼
 ⑤ 反解 IK：CasADi Opti + IPOPT
      │   变量 = 14 个手臂关节角；硬约束 = URDF 关节限位
      │   代价 = 50·‖位置误差‖² + 1·‖姿态误差‖² + 0·‖q‖² + 0.1·‖q − q_实测‖²
      │   热启动 = 本帧实测关节角
      ▼
 ⑥ 后处理：加权滑动平均滤波(0.4/0.3/0.2/0.1)
      │      → 冻结非受控臂的 7 个关节
      │      → 单周期增量限幅（--max-step-deg）
      │      → URDF 关节限位裁剪
      ▼
 ⑦ ZMQ 6002 下发：14 个具名手臂关节 + 严格递增的 timestamp
      │   机器人在 VLA 模式下写入 motor_cmd[15..28]
      ▼
    机器人手臂运动，回到 ② 循环（默认 50Hz）

  上行旁路（只看不影响控制）：6004 夹爪状态 100Hz + 6000 控制模式 50Hz → 状态行 / 非 VLA 告警
```

每帧都会打印两个误差，用来判断问题出在哪一环：

| 字段 | 含义 |
|---|---|
| `ik_err` | 反解精度：IK 输出经正解后离目标多远（求解器有没有解对） |
| `track_err` | 物理偏差：**实测**末端离目标多远（含腰部换算 + 伺服滞后） |

这两个误差每帧都在算，但"误差小"不等于"到位"（可能只是路过目标点）。**到位判定**见 §5：默认开启，会在到位时打一行 `✅ 到位 … 耗时 X.XXs`，没到位时报出原因（不可达 / 被挡住 / 仍在跟随 …）。

安全兜底（默认开启，一般不用改）：

- 状态超时（默认 250ms 收不到 6001 帧）→ 本帧不下发；
- IK 报错 → 保持上一帧命令，不把发散的解放到电机；
- 停发或退出后，机器人侧 VLA 指令超时会**保持最后一个有效 `arm_q`**（位置刚度保持，不会松手）。

## 2. 怎么跑起来

### 2.1 环境（Ubuntu 22.04，用 uv）

```bash
# ① 装 uv（一次性）
curl -LsSf https://astral.sh/uv/install.sh | sh

# ② 建环境 + 装依赖
cd g1_zmq_ik
uv venv --python 3.10                 # 生成 .venv（uv 会自动准备 Python 3.10）
uv pip install -r requirements.txt
#    等价的另一种写法（读 pyproject.toml）：uv sync

# ③ 激活（激活后下面的 python 命令直接可用；不想激活就在命令前加 `uv run`）
source .venv/bin/activate
```

装的四个包：`numpy` `pyzmq` `pin`(Pinocchio) `casadi`。

> **关于符号正解后端**：宇树原实现用 `pinocchio.casadi`，但它只由 conda-forge 提供（PyPI 的 `pin`
> 轮子不含）。本工程内置了一份等价实现：用同一份 URDF 数据搭 CasADi 符号表达式，实测与
> `pinocchio.casadi` 数值差 **2e-16**，代价函数/权重/关节限位/IPOPT 选项完全不变。
> 启动日志会打印用的是哪个：
>
> ```
> 符号正解后端: builtin(URDF->CasADi)     # uv/pip 环境（默认）
> 符号正解后端: pinocchio.casadi          # 若你装了 conda-forge 的 pinocchio，会自动优先用它
> ```
>
> 想强制指定用 `--fk-backend {auto,pinocchio,builtin}`。
> PyPI 的 `casadi` 轮子自带 IPOPT 插件（`libcasadi_nlpsol_ipopt.so`），不需要额外装 IPOPT。

### 2.2 启动顺序：**先让机器人跑起来，再启动脚本并给目标**

脚本要靠 6001 读关节角才能做正反解，而且 6002 的指令只在 VLA 模式下才驱动手臂，
所以**必须机器人侧先就绪，再启动上位机脚本**。

```bash
# ── 第 1 步：机器人侧（在机器人或它的遥控端操作）────────────────────────
#   ① 进入 Groot 状态：手柄 RB + X      （6001/6002 端口在这个状态里才 bind）
#   ② 切到 VLA 模式：  键盘 3  或 手柄 LB + A   （否则下发的关节角不驱动手臂）

# ── 第 2 步：上位机侧，启动脚本并同时给出目标 ──────────────────────────
python main.py --robot-ip 192.168.123.161 --arm right --pos 0.35 -0.20 0.10
```

**脚本跑起来的内部顺序**（对应第 1 节流程图）：

1. 加载 URDF、构建求解器（约 1~2 秒），然后订阅 6001，开始等 LowState；
2. 收到第一帧后：取出 14 个手臂关节角 → 正解出**当前**末端位姿并打印（`meas=`），
   并把"启动瞬间的末端朝向"锁定为目标姿态（所以只给位置、不写 `--rpy` 时手腕不会被拧）；
3. 目标从**第一帧就生效**：这一帧下发的命令 = 当前关节角 + 朝目标的一小步
   （每周期每个关节最多动 `--max-step-deg`，默认 2°），所以手臂是**从当前位姿限速平滑地移向目标**，
   绝不会一步跳过去；目标不可达时会在关节限位处停住（日志出现 `at_limit`）。日志里前几帧的
   `ik_err` 偏大是正常的 —— 它比较的是"被限速后的命令"与目标；
4. 之后每 50Hz 重复：读关节角 → 正解 → 反解 → 下发；
5. `meas` 与 `tgt` 重合、`ik_err`/`track_err` 落到零点几毫米，就说明到位了。

> **目标是启动时随命令一起给的**（`--pos` / `--delta` / `--rpy`）。也可以在运行中用
> `--interactive` 随时改；完全不给目标时，目标就是启动时的实测位姿，即"原地保持"。

退出：`Ctrl-C`。停发后机器人侧 VLA 指令超时会保持最后一个有效 `arm_q`（不会松手）；
要交还控制权就切回 `Gamepad`（手柄 `LB+X` / 键 `1`），手臂会按 Bezier 回到 `safe_home_q`。

#### 2.2.1 把真机常量写进配置文件（`--config`，可选）

机器人 IP、端口、夹爪标定、要不要 VLA 门控、到位后要不要自动闭爪 —— 这些每次都在命令行敲一遍很烦，可以写进
一个 JSON 文件，用 `--config` 带上：**文件里的键当默认值，命令行显式给的参数优先**。

```bash
cp robot.example.json robot.json      # robot.json 已进 .gitignore，不会污染版本库
python main.py --config robot.json --pos 0.35 -0.20 0.15
```

键名 = 命令行参数去掉 `--` 并把 `-` 换成 `_`（`--grip-on-arrive-soft` → `grip_on_arrive_soft`）；
数字写数字、开关写 `true`/`false`；以 `_` 开头的键会被忽略，可当注释用。写错键名**不会静默生效**：

```
配置文件 robot.json：14 项作为默认值生效（命令行显式给的参数优先）：arm='right' grip_open_cm=8.5 ...
配置里有不认识的键（已忽略）：robor_ip（键名应是参数名去掉 -- 并把 - 换成 _）
```

取值非法（比如 `"arm": "torso"`、`"pos": [0.3, 0.1]`）会**直接报错退出**，而不是带着错值跑。

| 想在文件里设 | 写什么 |
|---|---|
| 机器人 IP / 端口 | `"robot_ip": "192.168.123.161"`, `"gripper_port": 6004` |
| 非 VLA 时不下发 | `"require_vla": true` |
| 交互命令常开 | `"interactive": true` |
| 夹爪标定 | `"grip_open_cm": 8.5`, `"grip_qmax_rad": 5.6217`, `"grip_qmin_rad": 0.0` |
| 到位后力限软闭合 | `"grip_on_arrive_soft": 0.3` |
| 每次任务的目标 | `"pos": [0.35, -0.20, 0.15]`（也可以留在命令行上） |

**一份配置管两个程序**：`main.py` 读 `main` 段，`tools/detect_aruco_zmq.py`（相机 Tag 检测）读 `aruco` 段，
顶层只放 `_` 注释键；各程序只认自己那段，别人的段静默忽略（不会误报"不认识的键"）：

```json
{
  "_README": "两个程序共用这一份",
  "main":  { "robot_ip": "192.168.123.161", "require_vla": true, "interactive": true,
             "grip_open_cm": 8.5, "grip_on_arrive_soft": 0.3 },
  "aruco": { "marker_to_grasp": [0.0, 0.0, -0.015], "grasp_align_rpy": [0.0, 0.0, 0.0],
             "endpoint": "tcp://10.3.42.221:5556", "ids": [3] }
}
```

于是两个终端各一行（**视觉抓取流程**）：

```bash
# 终端 A：控制端（bind 6003 / 读 6001 / 发 6002）
python main.py --config robot.json
# 终端 B：Tag 检测端（检出标记 → 算抓取点 → PUSH 6003）
python tools/detect_aruco_zmq.py --config robot.json
```

**顺序**：机器人侧先进 Groot 状态、再切 VLA（键盘 `3` / 手柄 `LB+A`）→ 起 **A** → 起 **B**。
B 先起也能跑（6003 是 A 绑的，A 起来之前目标发不出去而已），但先 A 后 B 更好排查。

**视觉流程不要给 `--pos`**：目标应当全部来自 6003；给了 `--pos` 手臂会先跑到那个点、等第一帧标记
目标到了再改道（限速下不会猛，但纯属白跑）。只有"不用相机的联调"才需要 `--pos`，见上一节。

**跑通了看这三行**：

```
✅ 到位 [right] 实测残差 0.2mm/0.2° …                  ← 到位判定通过
开始软闭合[到位后 --grip-on-arrive-soft 0.3] …          ← 到位后自动力限软闭合
软闭合: right 接触冻结：接触（|τ|=0.31 ≥ 0.3） …        ← 夹住并冻住，不再加压
```

示例配置的 `main` 段已经带了 `"target_timeout": 3`：检测端挂掉时日志会提示"目标流失联"
（手臂保持在最后一条目标，不会松手也不会乱动）。

只想配一个程序时也可以不分段：所有键直接写在顶层（程序读"顶层 + 自己那段"）。

自检：`python tools/test_config.py`（31 项：类型转换、命令行优先、坏键只告警、非法值报错退出、
两个程序分段互不干扰、示例配置可直接用）。

### 2.3 目标的几种给法

```bash
# ① 启动时给绝对位置（默认 torso 系, m）+ 保持启动时锁定的末端朝向
python main.py --robot-ip <IP> --arm right --pos 0.35 -0.20 0.10

# ② 相对当前位姿的位移（前移 5cm、上移 3cm）
python main.py --robot-ip <IP> --arm right --delta 0.05 0 0.03

# ③ 指定末端朝向（rpy，单位 rad）
python main.py --robot-ip <IP> --arm right --pos 0.35 -0.20 0.10 --rpy 0 0 0

# ④ 双臂同时
python main.py --robot-ip <IP> --arm both --pos-right 0.33 -0.22 0.14 --pos-left 0.33 0.22 0.14

# ⑤ 轨迹测试：绕起始位置在 x-z 平面画 5cm 的圆
python main.py --robot-ip <IP> --arm right --demo circle --radius 0.05 --period 6

# ⑥ 运行中交互改目标（启动后输入 p x y z）
python main.py --robot-ip <IP> --arm right --interactive
```

交互命令：

```
p X Y Z      设置目标位置(默认 torso 系, m)   d DX DY DZ   在当前目标上叠加位移
r R P Y      设置目标姿态 rpy (rad)          a left|right|both  切换受控臂
t POS_MM ROT_DEG  设置到位判据（见 §5）       h   打印当前实测/目标/误差/到位状态
g [R [L]]    夹爪开合百分比（0=闭 100=全开）  例: g 0=双爪闭合  g 0 100  g=看当前
j            打印当前下发的 14 个关节角        ?   帮助              q   退出
```

#### 程序跑起来之后，怎么换目标？

| 情况 | 做法 |
|---|---|
| **程序还在跑**（没给 `--duration`，或还没到时间） | 三条通道任选：① 启动时带 `--interactive`，在终端敲 `p 0.35 -0.20 0.10`（`d dx dy dz` 是相对位移、`r r p y` 改姿态、`a left\|right\|both` 换臂）；② 直接用 6003 端口推一帧（见 2.4，**不需要** 启动时加任何参数）；③ 若启动时给了 `--demo circle/line`，它自己会一直动 |
| **程序已经退出**（Ctrl-C 或 `--duration` 到了） | 机器人保持最后的关节角（不会松手）。**用新的 `--pos` 重新启动程序**即可：启动时会先读当前关节角，手臂从当前位置平滑移到新目标，不会跳 |
| **想一直不重启地换目标** | 不加 `--duration` 启动，然后用 `--interactive` 或 6003 目标流 |

> 换目标后想确认生效：日志里 `tgt=` 立刻变成新值，`track_err` 开始下降；`p`/6003 是**覆盖**式赋值（绝对值），`d`/`delta` 是**相对上一条目标**累加。

#### 哪条手臂会被驱动？（`--arm` 说了算，不是目标说了算）

| 你写的 | 谁被驱动 | 说明 |
|---|---|---|
| `--arm right --pos X` | 右臂 | 默认值 |
| `--arm left --pos X` | 左臂 | |
| `--arm both --pos X` | **只有右臂** | `both` 时 `--pos` 视作右臂；左臂保持启动位姿（`--pos-left` 才是左臂） |
| `--arm both --pos-left A --pos-right B` | 双臂（各自独立） | 想要"双臂 + 命令行给目标"就用这个写法 |
| `--arm right --pos-left A` | **谁都不动** | 左臂目标被设了，但左臂关节被冻结 → 到位判定会给 `✗未驱动` |
| 运行中 `a left\|right\|both` | 切换受控臂 | 离开受控集合的臂被 `hold` 冻结保持 |

三条结论：

1. **驱动集合只由 `--arm`（或交互命令 `a`）决定**。非受控臂的 7 个关节每周期被覆写成上一帧值，
   给它设目标也不会动。
2. **状态行只打印受控臂**：看到一行 = 单臂在动，看到两行 = 双臂在动。日志里还有
   `目标系=…；受控臂=both` 一行可以直接确认。
3. **ZMQ 目标流里的 `arm` / `pos_left` / `pos_right` 只决定"给谁设目标"**，不会改变驱动集合，
   但它会把新出现的臂补进受控臂列表（`flags["arms"]`），便于你看到"这条臂收到目标了"。
   所以 `--arm right` 时流里下发左臂目标 → 左臂不会动，日志会明确报 `✗未驱动`
   （而不是含糊的"不可达"）。想让流真的驱动左臂，启动时就得用 `--arm both`。
### 2.4 持续下发目标（外部程序接口，ZMQ 6003）

控制循环本身就是**持续在跑**的（默认 50Hz：读关节角 → 正解 → 反解 → 下发），
所以机器人一直在收新的关节命令。如果你想让**别的程序**按自己的节奏一直改目标，
往主程序的 **6003 端口推目标**即可 —— 主程序 bind `PULL`，你的发送端 `PUSH` connect 过来。

帧格式（JSON，只认这几个字段，多余的忽略；`pos` 与 `delta` 二选一）：

```json
{"pos":   [0.33, -0.22, 0.13]}                 // 绝对位置（目标系, m；默认 torso_link）
{"delta": [0.005, 0.0, 0.0]}                   // 相对"上一条目标"的增量
{"rpy":   [0.0, 0.0, 0.0]}                     // 可选；不给就保持当前锁定的末端朝向
{"arm":   "right"}                             // 可选：right/left/both，默认用启动时的 --arm
{"pos_left": [...], "pos_right": [...]}        // 可选：一帧同时给两条手臂
```

规则：**最新优先**（积压时丢旧帧）、没有新目标时**保持上一条目标**、不合法帧只丢弃并告警。

现成的发送工具：

```bash
# 一次性：把右臂移到某个位置（发一帧就退出）
python tools/send_target.py --mode pos --pos 0.33 -0.22 0.13

# 一次性：相对上一条目标推 5mm（反复调用就是一步步挪）
python tools/send_target.py --mode delta --delta 0.005 0 0

# 连续：按 30Hz 一直推圆轨迹
python tools/send_target.py --mode circle --rate 30 --radius 0.05 --period 4

# 连续：按固定速度直线推进（位移速度 = delta × rate = 0.001×50 = 5cm/s）
python tools/send_target.py --mode delta --delta 0.001 0 0 --repeat 500 --rate 50

# 回放 CSV 轨迹（每行 t,x,y,z[,r,p,y]）
python tools/send_target.py --mode file --file traj.csv --rate 50
```

你有自己程序的话，直接按上面格式 PUSH 就行（`--target-port 0` 可关闭这个端口）：

```python
import zmq, json
s = zmq.Context().socket(zmq.PUSH); s.connect("tcp://127.0.0.1:6003")
for p in my_trajectory:                      # 想发多快就发多快
    s.send_string(json.dumps({"pos": list(p)}))
```


#### 实战：ArUco / AprilTag 检测 → 6003（`tools/detect_aruco_zmq.py`）

摄像头那侧现成的发送端就在仓库里：**`tools/detect_aruco_zmq.py`** —— 订阅图像流（ZMQ + JPEG/base64）
→ ArUco 检测 + solvePnP → 位姿换算到 **torso_link 系** → 限频/死区/跳变拒绝 → `PUSH` 到本程序的 6003。

```bash
uv pip install opencv-contrib-python        # 它需要 cv2.aruco（contrib 才有）

# ① 只检测：确认检测稳定、并看清标记三个轴在 torso 系下的指向
python tools/detect_aruco_zmq.py --no-send --endpoint tcp://10.3.42.221:5556

# ② 检测 + 下发（另一个终端先跑本程序的仿真，不需要机器人）
python main.py --sim --arm right --interactive --target-frame torso

```

**真机完整流程**（两个终端 + 顺序）：

```bash
# 机器人侧：手柄 RB+X 进 Groot → 键盘 3 / 手柄 LB+A 切 VLA
# 终端 A：控制端（先起它；不要给 --pos，目标全部来自 6003）
```

顺序与判据：**先 A 后 B**（6003 由 A bind；A 未起时 B 的目标发不出去，B 会先按 SNDTIMEO 丢几帧
而不会卡死）。B 起来后看终端 A 的日志依次出现 `✅ 到位` → `开始软闭合[到位后 --grip-on-arrive-soft …]`
→ `接触冻结`，就说明"检测 → 6003 → 手臂移动 → 到位 → 力限闭爪"整条链路通了。

**标记位姿 ≠ 抓取点**：检测给的是 **25mm 标记中心**的位姿，所以要用 `--marker-to-grasp DX DY DZ`
补上"标记中心 → 抓取点"的偏移。这个偏移是在**标记自身坐标系**里给的（由 solvePnP 的
`object_points` 定义）：**x / y 在标记平面内，z 垂直于标记向外**（标记正对相机时，z 指向相机）。

`--print-axes`（默认开）会把三个轴在 torso 系里的指向打出来，照着它决定往哪个轴偏：

```
axes(torso) x=(+0.01,-1.00,+0.03) y=(-0.99,-0.01,+0.05) z=(-0.03,-0.04,+1.00)
                                        ↑ 标记 z 轴指向 torso +z（朝上）= 标记贴在顶面、面朝上
```

| 标记贴在哪 | 轴打印的样子 | 抓取点偏移（例） |
|---|---|---|
| 盒子**顶面**、面朝上 | `z≈(0,0,+1)` | 抓腰部 → `0 0 -(盒高/2)`；抓顶部 → `0 0 -0.015` |
| 盒子**正面**、面朝相机/人 | `z≈` 水平指向你 | 抓中间 → `0 0 -(进深/2)` |
| 标记没对准抓取点（偏心） | x/y 分量 ≠ 0 | 按实际偏心量填 x/y |

#### 朝向：让夹爪跟着标记转（`quat`）

工具的抓取位姿是 `T_ee = T_marker @ [R_align | offset]`：

* `offset`（`--marker-to-grasp`）：标记中心 → 抓取点，在**标记自身坐标系**里给；
* `R_align`（`--grasp-align-rpy`）：夹爪相对标记的**对准旋转**（ZYX，在标记坐标系里给）。

算出来的位置与朝向都会发给 6003（`{"pos": [...], "quat": [...]}`），本程序会用 `quat` 作为**目标姿态**
（优先级高于 `--rpy` 与"启动时锁定的朝向"；运行中输入 `r` 会清掉 quat）。

`R_align` 的常见取值（标记贴在盒子顶面、面朝上、相机从上往下看时）：

值是**弧度**（`1.5708` = 90°，`3.1416` = 180°）—— 写成 `90` 会被当成 90 弧度，务必注意。

| `--grasp-align-rpy` | EE 探入方向（x） | 手指开合方向（y） | 适合 |
|---|---|---|---|
| `0 0 0` | 沿标记 x（水平） | 沿标记 y | 水平探入夹盒子 |
| `0 0 1.5708`（=90°） | 沿标记 x（水平） | 沿标记 x | 水平探入，开合方向转 90° |
| `0 1.5708 0`（=90°） | **−标记 z（竖直向下）** | 沿标记 y | 从上往下夹 |
| `0 1.5708 1.5708` | −标记 z（竖直向下） | 沿标记 x | 从上往下夹，开合方向转 90° |

⚠️ **朝向必须"可达"**：如果算出来的姿态让手臂拧到不可达的构型，反解会一直有残差、手臂到不了
（状态行会显示 `✗不可达` 或很大的 `ik_err`）。实测（合成标记、目标在躯干前方）：

| `--grasp-align-rpy` | EE 探入方向(torso) | 结果 |
|---|---|---|
| `0 0 0` | (0.12,**−0.99**,−0.12) 指向机器人自己右侧 | ✗ 不可达（`ik_err` 80mm/29.5°） |
| **`0 1.5708 0`** | (0.57,0.59,−0.58) 前-左-下 | ✅ 到位 4.48s，残差 0.07mm/0.03° |
| `0 0 1.5708` | (0.58,0.44,0.68) 前-左-上 | ✗ 不可达（147mm/30.5°） |
| `0 1.5708 1.5708` | (0.36,−0.05,−0.93) 竖直向下 | `ik_err` 4.4mm（可解，正在爬过去） |

**实操**：先用 `--no-send` 看打印的 `axes(ee/torso)` —— 确认 x（探入方向）是"你打算从哪边进盒子"的方向、
y（开合方向）横跨盒子的 3cm 那一维；不对就调 `--grasp-align-rpy`，上真机前再 `--dry-run` 确认 `ik_err` 很小。

**实测例子**（LIVOX 盒子立着、18cm 高、3cm 窄面朝机器人、标签平贴顶面；要"水平进入 + 手指左右开合 + 抓腰部"）：

```bash
python tools/detect_aruco_zmq.py --no-send --marker-to-grasp 0 0 -0.09 --grasp-align-rpy 0 0 -1.5708
# 判定标准（打印出来的 axes(ee/torso)）：
#   x ≈ (+1, 0, 0)  水平向前（从机器人朝盒子探入）   ← 探入方向
#   y ≈ (0, ±1, 0)  左右                            ← 手指开合，跨盒子的 3cm 窄边
#   z ≈ (0, 0, +1)  朝上
# 若 x/y 恰好互换（说明标签在盒顶是转 90° 贴的）→ 改成 --grasp-align-rpy 0 0 0（或 0 0 3.1416）
```
这组值已写进 `robot.example.json` 的 `aruco` 段（`marker_to_grasp` / `grasp_align_rpy`）。

### 2.6 末端速度 / 加速度（**已标定默认值，一般不用设**）

默认已经按"最平滑稳定"标定好：**10cm/s 上限 + 0.2m/s² 加速度**。不传任何参数就是这个行为。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--ee-speed` | **`0.10`** | 末端笛卡尔速度上限 m/s。传 `0` = 不限速 |
| `--ee-accel` | **`0.20`** | 末端加速度上限 m/s²（0→10cm/s 用时 0.5s）。传 `0` = 不限 |
| `--ee-rot-speed` / `--ee-rot-accel` | `0` | 姿态角速度/角加速度上限；`0`=不限 |
| `--ee-jerk` / `--ee-rot-jerk` | `0` | 加加速度上限（S 形曲线）。**实测在本架构下无收益，默认关闭**，见下文 |
| `--max-step-deg` | `2.0` | 每关节每周期最大增量（关节侧兜底） |

#### 标定过程与依据（`tools/tune_motion.py`）

工具会跑"从一个位姿移动到 12cm 外"的标准动作，量化并扫描参数网格：

```
峰值jerk ≈ 加速度/dt + 约5          ← 主项是加减速拐点的加速度阶跃
```

| 速度 | 加速度 | 峰值 jerk | 峰值 a | 速度纹波 | 到位过冲 | 12cm 到位 |
|---|---|---|---|---|---|---|
| 0.10 | **0.10** | 6.5 | 0.19 | 14.6% | 0.75mm | 2.42s |
| **0.10** | **0.20** | **10.1** | 0.37 | **10.6%** | **0.71mm** | **2.00s** |
| 0.10 | 0.30 | 17.3 | 0.59 | 8.8% | 0.62mm | 1.86s |
| 0.10 | 0.50 | 53.5 | 1.11 | 6.0% | 0.83mm | 1.74s |
| 0.12 | 0.20 | 10.0 | 0.37 | 12.6% | 0.71mm | 1.84s |
| 0.06 | 0.20 | 12.1 | 0.40 | 6.5% | 0.67mm | 2.84s |

选 **0.10m/s + 0.20m/s²** 的理由：综合"平滑度(峰值jerk/纹波) + 过冲 + 到位时间"最优；
加速度再大（0.3/0.5）峰值 jerk 立刻涨到 17/53（冲击感明显），再小（0.1）则到位时间多 20% 而
平滑度提升有限。**另外实测确认了几个前提**：

* 静止保持 200 周期时关节抖动仅 0.0064 mrad/s（= 浮点噪声量级）→ **IK 每周期解算本身不引入抖动**，
  所以平滑处理只需要管运动曲线，不需要额外滤波；
* 给了 `--ee-accel` 后速度曲线是**梯形**：加速段实测 a 恒定（0.200m/s²）、巡航段实测稳定
  （100.0mm/s）、临近目标按 `√(2·a·剩余距离)` 提前减速，**无过冲**；
* `--ee-jerk`（S 形）实测**没有收益**：峰值 jerk 与不加时相同（10.0 vs 10.1），中间值（0.5~5）
  反而更差 —— 因为峰值 jerk 的主项来自**路径方向变化**（IK 每周期解出的运动方向在变），
  只限制速度幅值的方案管不到它。故默认关闭，参数保留供实验。

```bash

# 想让手臂尽快过去（更快但冲击更大）

# 完全不限速（回到"IK 能多快就多快"）

```

日志可直接核对：`v=` 是本周期的实际末端速度、`a=` 是实际加速度、`末端限速 xN` 是钳制系数。

输出侧量纲；`kp`/`kd`/`mode` 属于机器人侧 config，帧里传会被忽略并 warn）：

```json
{"cmd":"action",
 "action":{"kLeftShoulderPitch.q":-0.20, ..., "remote.lx":0.0, ...,
           "gripper":{"right":{"q":0.0},"left":{"q":5.0}}},
```

本程序的三种下发方式：

```bash
# ① 启动时给（--grip-unit 默认百分比：0=闭合 100=全开）
python main.py --robot-ip <IP> --arm right --pos 0.30 -0.10 0.05 --grip 0
python main.py ... --grip-right 0 --grip-left 100          # 分别给两侧
python main.py ... --grip 4.25 --grip-unit cm              # 用厘米给（内壁开口）
python main.py ... --grip 2.8109 --grip-unit rad           # 直接给弧度

# ② 运行中交互（百分比；只给一个数=两侧同值）

g 0 100      # 右闭、左开
g            # 看当前【目标 vs 实测】

{"grip_rad": {"right": 0.0}}                               # 直接给弧度；只动夹爪也能单独发一帧

# ④ 到位后自动闭爪（与 --on-arrive 正交，可一起用）
python main.py ... --pos 0.30 -0.10 0.05 --grip-on-arrive 0
```

**开合百分比 ↔ 弧度 ↔ 厘米的换算**（线性）：

```
百分比 = q / q_max × 100        （0% = 全闭, 100% = 全开）
厘米   = 百分比 / 100 × 实测全开(cm)     ← 你的真机实测值是 --grip-open-cm（默认 8.5）
弧度   = 百分比 / 100 × q_max           ← q_max 是机器人侧标定的张开角（--grip-qmax-rad，默认 5.6217 = 322°）
```

> **要现场核对一次线性假设**：让夹爪停在 50%（`g 50`），量一下内壁开口是不是 ≈4.25cm。
> 若明显不是线性（比如机构是连杆），就把 `--grip-open-cm` 换成"你实际关心的那段"的等效值，
> 或者直接用 `--grip-unit rad` / `grip_rad` 绕过百分比换算。

⚠️ 上游提醒（照抄）：**量程的 clamp 是唯一的机械限位保护** —— `dex1_1_service` 只把 `q×gear` 直发串口，
不校验范围。所以 `config.yaml` 里的 `q_min/q_max` 必须在真机上实测后设定；本程序在发送前也会按
`--grip-qmin-rad/--grip-qmax-rad` clamp 一次并告警（契约："clamp 不丢帧"）。

#### 力限软闭合（`gc` / `--grip-on-arrive-soft`）—— 抓盒子用这个

`q=0`（全闭）不该用来抓盒子：那是**位置指令**，伺服会一直用约 `kp × (指令 − 实际)` 的力顶着物体
（刚性盒子会被压坏；指令越接近 0，力越大）。上游只给了 `q`、没有力控帧，所以「夹到东西就停」
只能在上位机闭环 —— 就是 `grip_control.SoftClose`：

```
第一段（逼近）：目标 q 以 --grip-soft-rate（默认 1.5 rad/s ≈ 2.3cm/s 开口）往闭合方向推
第二段（压紧）：一旦 |tau| >= 30%×阈值（视为接触），换成慢 10 倍（0.15 rad/s）继续压（单向，
               接触过就一直慢，不会因为 tau 回落又加速）
超标退回  ：逼近段是「盲走」——力反馈要下一个周期才看到，而这一周期的指令已经压进去了，所以
               会出现「第一次读到就超标」。此时**退回最后一次确认还没接触的实测位置**，等压力
               释放（|tau| < 5%×阈值，最多 20 周期 = 0.4s）再慢压。每侧最多退 2 次，之后才冻结。
               没有这一步时实测过 3cm 盒/刚度 8 会停在 3.3 倍阈值；加上后退回重压是 1.3%。
冻结       ：|tau| >= 阈值（--grip-soft-tau，默认 0.3）→ 立刻冻结该侧目标（保持这个轻压紧力）
次级判据   ：被物体挡住（实测比指令更张开）且 |dq| < 0.02 连续 4 周期，**而 tau 始终低于接触
               阈值**（软物体没有力信号可依赖）→ 目标停在「实测开口 − 1mm」，留 1mm 过盈轻夹持
               （位置控制下不留过盈就等于没夹住）。tau 一旦过了接触阈值，就以力判据为准。
安全       ：6004 超时 0.5s 没有新帧就中止（没有力反馈不能力控，否则等于盲目压到底）
```

```bash
# 到位后自动软闭合（tau 到 0.3 就停）——最省心的抓取方式
python main.py ... --pos 0.30 -0.10 0.05 --grip-on-arrive-soft 0.3

gc            # 运行中软闭合到默认阈值
gc 0.2        # 软闭合到 |tau| >= 0.2
go            # 张开/释放（两侧 100%）

# 6003 目标流里（Tag 程序可以一帧说「到位了慢慢合上」）
{"grip_close_tau": 0.3}            # 可选 "grip_sides": ["right"]
```

**实测（假盒子 6cm、刚度 4 tau 每 cm；`tools/mock_gripper_box.py`）对照**：

| 方式 | 指令停在 | 接触瞬间过盈 | 稳态 tau | 结果 |
|---|---|---|---|---|
| `g 0`（位置闭合） | 0cm（=全闭） | 6.0cm | **24.0** | 会夹坏 |
| `gc 0.3`（软闭合） | **5.92cm** | **0.80mm** | **0.31** | 轻轻压住 ✓ |

硬物体上差别更明显（3cm 盒、刚度 8 τ/cm）：退回重压前是 3.3 倍阈值，重压后是 1.3%（τ=0.304）；
软物体（tau 一直不抬头）走「被挡住」兜底，停在实测开口 −1mm、τ≈0.10，宁小不大。

这就是「抓盒子」的正确姿势：**不需要知道盒子宽度**，靠 tau 判断压住了没有，压紧力由
`--grip-soft-tau` 决定。阈值要在真机上试：太小 → 夹不住（tau≈0 且物体打滑）；太大 → 压痕/变形。

#### 模式门控：`--require-vla`

`--require-vla` 让程序**只在机器人处于 VLA 模式时才真正下发 6002**：

* 不在 VLA 时：仍然读状态、解 IK、打印（状态行显示 `[未下发]`），但不占用 6002；
* 回到 VLA 时：自动 `reanchor()` —— 丢掉旧的指令连续性，**从当前实测位姿平滑起步**，
  避免「暂停期间手臂被别的方式挪走、恢复后第一帧把它拽回去」。

实测（12s：vla 5s → gamepad 4s → vla）：假机器人收到的帧数从 **500+ 降到 300+**（gamepad 期间一帧没发），
日志出现 `暂停下发（模式=gamepad）` 与 `恢复下发（模式=vla）` + `重新锚定到实测位姿`。

其他行为（上游契约）：夹爪目标**发一帧就够**（机器人侧 latch 并以 100 Hz 无条件重发）；
**收到第一个目标之前不发任何指令**；退出 VLA / 偏差保护**都不自动松爪**；松爪是显式动作
（手柄 `RB+A` / 键盘 `g`）。本程序退出后机器人侧仍会重发最后目标 → 抓取力保持。

## 3. 坐标系与目标定义

### 3.1 目标系：`torso_link`（默认）还是 `pelvis`

| 坐标系 | 定义 | 什么时候用 |
|---|---|---|
| **`torso_link` 系（默认）** | 躯干 link 的坐标系 —— **手臂就挂在它上面**（`left/right_shoulder_pitch_joint` 的 parent 是 `torso_link`） | `--target-frame torso`（默认）。**腰怎么转都不影响手臂解算**：目标是"相对躯干的位置"，Tag 检测/抓取通常就是这种语义 |
| **`pelvis` 系** | URDF 根 link `pelvis`（**骨盆**）；x 前、y 左、z 上；pinocchio 的世界系与它重合 | `--target-frame pelvis`（旧行为）。腰角参与换算：同一个骨盆系目标，腰一转就需要不同的手臂构型 |

两个系之间只差一个**常量**（实测自 URDF）：

```
C = FK(腰=0) 时 torso_link 的位姿 = 平移 (-3.964, 0, +44.000) mm，姿态 = 单位阵
torso 系目标  ──▶ 求解系：T_locked = C @ T_torso            （与腰角无关）
pelvis 系目标 ──▶ 求解系：T_locked = A0 @ inv(A) @ T_pelvis  （A = FK_full(腰=实测值) 的手臂链根帧）
```

`--check` 会把这两个数打印出来核对；`tools/test_target_frame.py` 专门验证这套语义（13 项）。

**要点**：`pos` 目标、日志里的 `tgt=`/`meas=`、`track_err`、到位判定**全都用同一个目标系**，所以两组数字可以直接相减对比。`--waist state|zero` 只在 `--target-frame pelvis` 下有意义。

### 3.2 末端点与腰部

| 名称 | 含义 |
|---|---|
| **末端点（EE）** | `L_ee`/`R_ee` 挂在 `*_wrist_yaw_joint` 上、沿轴偏 `--ee-offset`（默认 **0.152m** = Dex1 夹爪抓取中心）。**目标位置、`track_err`、到位判定说的都是这个点**。 |
| **腰部** | 反解只输出 14 个手臂关节，腰由机器人全身策略驱动。`--target-frame torso`（默认）下腰角**不参与**手臂解算；`--target-frame pelvis` 时用 6001 读到的实测腰角换算（`--waist state`），或按 xr_teleoperate 的"腰=0"假设（`--waist zero`）。 |

### 3.3 模型变体（手 / 夹爪）与 `--ee-offset` 怎么选

仓库里有两份官方 URDF，同一份代码都能用（换 URDF 时"要锁定的关节"由程序自己从 URDF 推导，不用改代码）：

| 变体 | URDF | 全模型 nq | 末端关节 | `--ee-offset` 建议值 |
|---|---|---|---|---|
| **G1-29DoF + Dex1 夹爪**（默认，`mode_machine=15`） | `assets/g1/g1_29dof_mode_15_with_dex1_1.urdf` | **33**（腿12+腰3+夹爪4+臂14） | `left/right_dex1_finger_joint_1/2`（2 个/手，prismatic） | **0.152** = 抓取中心 |
| G1-29DoF + Dex3 三指手（原默认） | `assets/g1/g1_body29_hand14.urdf` | 43（腿12+腰3+手指14+臂14） | `left/right_hand_*`（7 个/手） | 0.05 = 掌根（xr_teleoperate 口径） |

两份 URDF 的**关节限位完全相同**，手臂链几何差 5.0mm（腕部不同批次），所以换模型后 IK 约束不变、末端点只按 `--ee-offset` 平移。

`--ee-offset` 是"从腕部 yaw 关节沿夹爪接近方向往前多少米"。Dex1 夹爪的实测几何（官方 mesh 量出来的，距 `wrist_yaw` 关节）：

| 你想要的"末端点" | 建议 `--ee-offset` | 说明 |
|---|---|---|
| 抓取中心（**默认、推荐**） | `0.152` | 两指之间、抓取段中点：Tag 标在"物体该被夹住的位置"时用这个 |
| 指尖平面 | `0.185` | 手指最前端：Tag 标在"指尖该碰到哪里"时用 |
| 夹爪根部（法兰） | `0.111` | 夹爪底座外端 |
| 掌根（旧 Dex3 口径） | `0.05` | 落在夹爪体内，仅用于和旧数据对齐 |

> 换模型后**先把 `--dry-run` 跑一遍**：日志里 `meas=` 就是当前末端点位置，确认它和你用尺子量到的夹爪位置一致，再上目标。

## 4. 日志怎么读

```
[   1.35s] #60   0.1ms meas=(+0.285,-0.215,+0.134) tgt=(+0.350,-0.200,+0.100) ik_err=0.0mm/0.0° track_err=74.4mm/14.1° ik=1.2ms v=100.0mm/s a=0.00m/s² 关节限速 3 个; 末端限速 x0.26 到位=✗跟随中(74.4mm)
```

| 字段 | 含义 |
|---|---|
| `#50` | 第几个控制周期 |
| `0.0ms` | 状态帧延迟；持续超过 `--state-timeout` 就不再下发 |
| `meas` / `tgt` | 实测末端位置 / 目标位置（**目标系**, m；默认 torso_link） |
| `ik_err` | 反解精度（在求解坐标系里比较，与腰无关） |
| `track_err` | 实测离目标的真实偏差 |
| `ik=7.4ms` | 本周期 IK 耗时 |
| `v=100.0mm/s` | 本周期实际末端速度（上限见 §2.6 的 `--ee-speed`） |
| `a=0.00m/s²` | 本周期实际末端加速度（只在 >0 时显示） |
| `末端限速 x0.26` | 末端速度钳制系数，<1 表示本周期被限速（§2.6） |
| `限速 N 个关节` | 有 N 个关节被单周期限幅 |
| `[未下发]` | 本周期没发（状态超时 / IK 失败 / 尚无状态帧） |
| `到位=…` | 到位判定的短标注（见 §5）：`✅(0.1mm, 1.29s)` / `…0.12/0.20s` / `✗跟随中(12.4mm)` / `✗不可达` 等 |
| `夹爪=R21%(1.8cm)/L100%(8.5cm) τ1.50/0.02` | 夹爪**实测**开合百分比 / 内壁开口 cm（由 6004 的 q 按线性换算）/ 力矩估计 τ。见 §2.7 |
| `模式=vla` | 机器人当前控制模式（来自 6000）；不是 `vla` 时手臂不会动，且会打告警。见 §2.7 |

## 5. 到位判定（实测末端是否已稳定到达目标）

**默认开启**，只做判断和报告，默认不改变任何控制行为。核心是：**判实测、要连续、要停住、要可达、数据要新鲜**。

### 5.1 判据（全部满足并连续保持 `--arrive-dwell` 秒才算到位）

| # | 判据 | 默认 | 为什么需要 |
|---|---|---|---|
| ① | 实测残差 `track_err` ≤ `--arrive-pos` / `--arrive-rot` | 2mm / 1° | 到位与否只看**实测**（`ik_err` 是"指令离目标多远"，手臂没跟上时它可能很小） |
| ② | 反解残差 `ik_err` ≤ `--arrive-ik-pos` / `--arrive-ik-rot` | 3mm / 2° | 目标在可达范围外时手臂只是"停在最近处"，不能算到位；填 `0` = 不判可达性 |
| ③ | 以上判据连续满足 | `--arrive-dwell 0.2` s | 单帧压线不算到位（噪声、单帧抖动） |
| ④ | 末端速度（EMA）≤ `--arrive-speed` | 15mm/s | 目标快速移动时手臂会"**路过**"目标点：位置误差瞬时很小但根本没停住 |
| ⑤ | 关节速度（EMA）≤ `--arrive-joint-speed` | 10°/s | 末端"恰好"不动、但关节还在零空间里漂 |
| ⑥ | 状态帧新鲜（≤150ms）且本周期真的下发了 | — | 数据僵住时不判定，避免把"旧数据"当成到位 |

进入用判据①的阈值，**离开用它的 2 倍**（滞回），避免在阈值附近来回刷屏。

**只有"目标真的变了"才重新计时**：目标位姿变化超过 0.1mm / 0.006° 才算新目标。ZMQ 目标流以 30Hz 重复下发同一条目标不会被当成新目标 —— 否则驻留计时永远清零，静态目标永远判不出到位。

没到位的原因会在 `--arrive-timeout`（默认 5s）时报告一次，**不影响控制**（填 `0` 关闭）。原因分类：

| 原因 | 含义 | 怎么办 |
|---|---|---|
| 目标不可达 | 反解残差大（且手臂已停稳） | 换一个可达的目标；关节限位表用 `python main.py --list-limits` 打印 |
| 疑似被挡住 | 末端几乎静止但离目标很远（>max(5×判据, 10mm)） | 检查是否撞到东西 / 关节被限位卡住 |
| 临界未达 | 已停稳、只差一点但没进判据 | 判据过严或存在稳态误差：`t 5 2` 放宽，或查 `--w-reg` |
| 未驱动 | 这条臂没被 `--arm` 选中，关节被逐帧冻结保持（给它设目标也不会动） | 用 `--arm left/right/both` 重启，或交互 `a both`；见 §2.3 |
| 仍在跟随 | 还在动（限速追赶 / 伺服滞后 / 腰角换算偏置） | 正常；若一直如此看日志里的 `[腰未参与换算, 偏差Xmm]` |
| 仍在运动 | 速度还没降下来 | 等一会儿 |
| 状态超时 / 未下发 / 无状态帧 | 数据不可信或没发指令 | 见 §7 第 1 条 |

### 5.2 日志长什么样

状态行末尾多一个字段，每 `--print-every` 帧刷新（交互模式下敲 `h` 看）：

```
[   4.55s] #200   0.1ms meas=(+0.350,-0.200,+0.100) tgt=(+0.350,-0.200,+0.100) ik_err=0.1mm/0.0° track_err=0.1mm/0.0° ik=0.2ms v=0.0mm/s 到位=✅(0.07mm, 3.76s)
```

事件（**每条目标各报一次**，不会刷屏）：

```
  ✅ 到位 [right] 实测残差 0.1mm/0.02°，反解残差 0.1mm/0.02°，末端 1.1mm/s、关节 0.4°/s，驻留 0.22s，耗时 1.29s，目标 (+0.350,-0.200,+0.100)
  ⏱ 未到位 [right] 目标变更后 3.0s 仍未进入判据：实测残差 785.2mm/13.96°，反解残差 785.2mm/13.96°，末端 0.0mm/s、关节 0.0°/s；原因：目标不可达（反解残差大，手臂停在能到的最近处），目标 (+1.200,-0.200,+0.500)
  ↩ 离开到位区 [right] 实测残差 5.1mm/0.10° 超过离开阈值 4.0mm/2.00°（到位阈值 ×2.0），重新开始计时
```

退出时汇总（`--arm both` 时逐臂给出）：

```
到位统计: 总计 目标 1 个 / 到位 1 次 / 平均耗时 1.29s / 最慢 1.29s；right: 目标 1 个 / 到位 1 次 / 末次耗时 1.29s / 末次实测残差 0.1mm/0.02° / 当前 已到位
```

### 5.3 到位之后做什么：`--on-arrive`

| 取值 | 行为 |
|---|---|
| `none`（默认） | **只报告**，控制行为完全不变 |
| `freeze` | 停止自动目标推进：`--demo` 轨迹不再推进、ZMQ 目标流被丢弃，继续下发最后一条命令锁住位姿；输入交互命令 `p`/`d`/`r` 立即解冻 |
| `exit` | 到位即退出（脚本化调用：跑完就走，不用 `--duration` 掐时间） |

```bash
# 到位就退出，终端直接给出残差和耗时
python main.py --robot-ip 192.168.123.161 --arm right --pos 0.35 -0.20 0.10 --on-arrive exit

# 到位后锁死（目标流/轨迹不再推动手臂），需要动时输入 p x y z 解冻
python main.py --robot-ip 192.168.123.161 --arm right --interactive --on-arrive freeze
```

### 5.4 调参与边界情况

- 交互模式里随时改判据：`t 5 2` = 放宽到 5mm/2°，`t 0.5 0.2` = 收紧。
- `--no-arrive` 彻底关掉判定（行为回到没有这个功能之前）。
- 跑轨迹（`--demo circle` / `--line`）**不会**报到位 —— 目标一直在动，这是对的；判据④会拦住"路过"式的假到位。
- `--w-reg 0.02`（复现宇树原版手感）会让 `ik_err` 稳定在 2~3mm：判据②默认 3mm 正好容得下。若把 `--arrive-ik-pos` 压到 1mm 以下，会一直报"不可达"—— 这不是 bug，是原版算法的固有偏置（见 docs/对照宇树源码.md §8）。

| `--arrive-ik-pos` `--arrive-ik-rot` | `3` mm `2` ° | 到位判据②：反解残差上限（`0`=不判可达性） |
| `--arrive-dwell` | `0.2` s | 到位判据③：连续满足时长 |
| `--arrive-speed` `--arrive-joint-speed` | `15` mm/s `10` °/s | 到位判据④⑤：末端 / 关节速度上限 |
| `--arrive-timeout` | `5` s | 目标变更后多久未到位就报告一次原因（不影响控制）；`0`=不报告 |
| `--on-arrive` | `none` | 到位后动作：`none` 只报告 / `freeze` 冻结自动目标推进 / `exit` 到位即退出 |

完整参数：`python main.py -h`

## 7. 跑不起来先看这三条

1. **日志一直 `尚无状态帧`**：机器人侧还没就绪（见 2.2 第 1 步）→ `ping <IP>` → 在机器人上 `ss -lntp | grep 600` 看端口是否在监听。
2. **日志正常刷新、但手臂不动**：机器人不在 VLA 模式（见 2.2 第 1 步）—— 现在会**自动告警**：状态行显示 `模式=gamepad`，并每 5 秒打印一次「机器人当前不在 VLA 模式…」（见 §2.7）；或者你给的目标本来就等于当前位姿。
3. **`track_err` 一直降不下来**：看状态行末尾的到位标注和 `⏱ 未到位` 那行给的原因 —— 目标不可达（`✗不可达` + `at_limit`）；或用了 `--waist zero` 而真机腰角非 0（`✗跟随中`，日志会提示 `[腰未参与换算, 偏差 Xmm]`）；或 `--max-step-deg` 太小、跟不上目标移动（`✗跟随中`，日志有 `限速 N 个关节`）。原因清单见 §5.1 表格。

4. **抓盒子怕夹坏 / 不知道该给多少百分比**：用 `--grip-on-arrive-soft 0.3`（运行中 `gc`）——
   力限软闭合会「慢闭到 tau 达标就停」，不需要知道盒子宽度；原理与实测对照见 §2.7。
   离线复现：`python tools/mock_gripper_box.py --box-cm 6`。
5. **夹爪不动 / 夹爪报量程告警**：状态行 `夹爪=` 是**实测**值（来自 6004）；`g` 命令会同时打印
   **目标 vs 实测**。若目标发了但实测不动：机器人侧 `config.yaml` 的 `FSM.Groot.gripper.q_min/q_max`
   没按真机标定（或我们的 `--grip-qmin-rad/--grip-qmax-rad` 与它不一致）；若日志出现
   `夹爪 q=… 超出标定量程 -> clamp`，就是这里被夹住了。注意：**夹爪目标与手臂模式无关**，
   `Gamepad/Navigation/VLA` 下都会生效（只有手臂通路受 VLA 模式约束）。
