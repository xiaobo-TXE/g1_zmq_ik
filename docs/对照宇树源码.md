# 与宇树 xr_teleoperate 源码的逐行对照

对照对象：`unitreerobotics/xr_teleoperate`，文件 `teleop/robot_control/robot_arm_ik.py`，
类 `G1_29_ArmIK`（commit `817fb00`, 2026-09-07）。

**结论：反解（IK）是原算法的忠实移植，正解（FK）与反解共用同一个 `pinocchio.casadi` 符号模型。**
下面的行号可直接对照阅读。

---

## 7. 本工程新增、且可关闭的两项

| 新增 | 作用 | 如何退回原版行为 |
|---|---|---|
| 腰部坐标换算 `fk_pelvis / pelvis_to_locked`（L208-243） | groot 的全身策略会驱动腰关节 12/13/14，而 6002 只能下发手臂；本项用实测腰角把 pelvis 系目标精确换算到缩链模型坐标系 | `--waist zero`：完全等价于原版"腰锁死=0"的假设 |
| `SymbolicArmKinematics`（内置符号正解） | `pinocchio.casadi` 只由 conda-forge 提供，PyPI 的 `pin` 轮子不含它；本项用同一份 URDF 数据（关节链/关节原点 SE3/关节轴/q 索引）搭出 CasADi 符号正解，使 uv/pip 环境也能跑原算法 | `--fk-backend pinocchio`：强制用 `pinocchio.casadi`（没有则报错） |

## 8. 实测（pinocchio 3.1.0 + casadi 3.6.7，与 xr_teleoperate 官方 requirements 同版本）

| 项目 | 结果 |
|---|---|
| `pinocchio.casadi` 的 `Model/framesForwardKinematics/log3` | 全部可用 ✓ |
| CasADi 符号 FK vs Pinocchio 数值 FK | 逐元素最大差 **2.22e-16** ✓ |
| 原版误差 Function 在真值构型上的自残差 | **0.00 µm / 1.7e-14°** ✓ |
| IPOPT 单帧耗时（50Hz、目标平滑移动） | 首帧 12.3ms，之后 **mean 5.3ms / max 12.3ms** |
| IPOPT 单帧耗时（目标大幅跳变、从零位冷启动） | 30~40ms（`max_iter=30` 会把迭代跑满） |
| 闭环残差（默认权重） | 约 **3mm / 0.5°**（见下） |
| 闭环残差（`--w-reg 0`） | **0.001 mm** |

### 关于那 3mm：是原版权重带来的系统性偏置，不是实现问题

在真值构型 `q_true` 处代价 `50*||e_pos||² + ||e_rot||² + 0.02*||q||² + 0.1*||q-q_ref||²`
并不为零（正则项 `0.02*||q_true||² = 0.0499`），所以 IPOPT 会**主动用几毫米的位置误差
去换更小的正则代价** —— 实测 IPOPT 解的代价 0.048359 < 真值处的 0.049889，即它确实找到了
更优解；把 `W_REGULARIZATION` 置 0 后残差立刻降到 **0.0011 mm**。

### 还有第二个后果：静止保持时会缓慢漂移

平滑项锚定的是**本帧实测角**，正则项把解往零位拉，两者拉扯会让构型缓慢向零位爬。
固定目标保持 120 帧（50Hz 下 2.4s）实测：

| 权重 | q 最大漂移 | 肘关节漂移 | 最终末端残差 |
|---|---|---|---|
| `w_reg=0`（本工程默认） | **0.0004 rad** | 0.00005 rad | **0.0007 mm** |
| `w_reg=0.02`（原版） | 0.2635 rad | 0.0525 rad | 2.389 mm |

而 `w_reg=0` 并不会让冗余自由度失控 —— 零空间锚定由平滑项 `0.1*||q-q_ref||²` 承担
（`q_ref` = 实测角，等于"停在当前构型"），比原版的"朝零位拉"更可预测。

结论：**本工程默认 `--w-reg 0`（精度优先）**；要复现 xr_teleoperate 原版手感加 `--w-reg 0.02`。

## 9. 两个符号正解后端的等价性实测

| 项目 | 结果 |
|---|---|
| 内置 `SymbolicArmKinematics` vs Pinocchio 数值正解 | 逐元素最大差 **2.22e-16** |
| 同一批目标下 `--fk-backend pinocchio` vs `builtin` 的解 | 关节最大差 **5.16e-13 rad**，末端残差差 **1.1e-11 mm** |
| 两者在原版误差 Function 上的自残差（真值构型） | **0.00 µm** |

结论：uv/pip 环境用内置后端得到的结果与 `pinocchio.casadi` 原路径等价（差异仅来自 IPOPT 的浮点噪声）。
