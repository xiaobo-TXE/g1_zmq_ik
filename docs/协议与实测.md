# ZMQ 协议详解与实测数据

本文是 `README.md` 的详细附录：ZMQ 协议的逐字段说明、离线/在环实测数据、常见问题、
以及与原版 xr_teleoperate 的完整差异清单。日常使用只需要看 `README.md`。

## 能不能把 xr_teleoperate 的正反解单独拿出来？

**能，而且几乎不用改数学部分。** `teleop/robot_control/robot_arm_ik.py` 是个"伪独立"模块，实际只依赖：

| 原版依赖 | 处理方式 |
|---|---|
| `casadi` + `pinocchio` | 保留，这是算法本体 |
| `pinocchio.casadi`（符号正解） | 只由 conda-forge 提供；本工程额外内置了等价实现 `SymbolicArmKinematics`（数值差 2e-16），因此 uv/pip 也能跑原算法 |
| `meshcat` / `pinocchio.visualize` | **去掉**（可视化要 200MB meshes，本工程不需要） |
| `logging_mp`（xr_teleoperate 自带） | **换成 stdlib `logging`** |
| `teleop.utils.weighted_moving_filter` | 已内联进 `g1_ik.py`（去掉 matplotlib） |
| `pin.rnea` 力矩计算 | **去掉**：ZMQ 6002 协议只有关节角，没有 tau 字段 |
| `assets/g1/g1_body29_hand14.urdf` + meshes(201MB) | 只拷 **URDF(51KB)**；改用 `buildModelFromUrdf` + `buildReducedModel`，不建几何模型 → **不需要 meshes** |
| 模型 pickle 缓存 | 保留，但加了 URDF `mtime+size` 校验（原版缓存永不失效，改了 URDF 会静默加载旧模型） |

抽取后的数学与权重**逐行保持原样**（`g1_ik.py` 顶部注释里写明了对应关系）：

```
minimize  50*||e_pos||² + 1.0*||e_rot||² + 0.02*||q||² + 0.1*||q-q_last||²
s.t.      lowerPositionLimit ≤ q ≤ upperPositionLimit        (URDF 关节限位)
e_pos = p_cur - p_target
e_rot = log3(R_cur @ R_targetᵀ)
求解器: CasADi Opti + IPOPT (max_iter=30, tol=1e-4, acceptable_tol=5e-4, 热启动)
```

本工程在此之上**新增**了（都不改变原算法）：
1. `G1ArmModel.fk()` / `fk_pelvis()` —— 正解，以及「用实测腰角做坐标换算」；
2. `ArmIKDLS` —— 一个不依赖 CasADi/IPOPT 的 Levenberg–Marquardt 回退求解器（也是交叉验证工具）；
3. `self_test()` —— FK→IK→FK 闭环自检（实测数字见本文「已验证的结果」一节）。

## ZMQ 协议（摘自 groot-control 源码，逐条对照）

**两个端口方向相反，且都是机器人在 `bind`，上位机只能 `connect`：**

| 端口 | 机器人侧 | 上位机侧 | 方向 | 内容 |
|---|---|---|---|---|
| **6001** | `PUB` bind `tcp://*:6001` | **`SUB` + connect** | 机器人 → 上位机 | LowState（**读关节角走这条**） |
| **6002** | `PULL` bind `tcp://*:6002` | **`PUSH` + connect** | 上位机 → 机器人 | 14 个手臂关节目标 + 行走速度 |

端口配置在 `deploy/robots/g1_29dof/config/config.yaml` 的 `Groot.zmq.port=6002` / `state_port=6001`；
socket 在 `State_Groot::enter()` 里启动、`exit()` 里停止 —— **只有机器人处于 `Groot` 状态时端口才存在**。

### 6001 上行帧（`LowStateBroadcaster.h:54-91`）

单帧裸 JSON 字符串，**没有 ZMQ topic 前缀**（`"topic"` 只是 JSON 里的一个字段）：

```json
{"topic":"rt/lowstate","data":{
  "motor_state":[{"q":0.1,"dq":0.0,"tau_est":0.0,"temperature":30.0}, ...共 35 项...],
  "imu_state":{"quaternion":[w,x,y,z],"gyroscope":[x,y,z],"accelerometer":[x,y,z],"rpy":[r,p,y],"temperature":0},
  "wireless_remote":"<base64>","mode_machine":5}}
```

* `motor_state` **固定 35 槽**，本部署只用 `0..28`，`29..34` 恒 0。
* 手臂角 = `motor_state[15..28].q`（左臂 15-21，右臂 22-28），顺序与 xr_teleoperate 的
  `G1_29_JointArmIndex` 逐位一致 —— **两边可以直接对接，不需要重排**。
* 发送条件：500Hz 轮询 + `tick()` 变化才发 + `SNDHWM=2` + `dontwait`
  → **攒不住、不重传、无序号**，JSON 里也没有 `tick` 字段，丢帧无法从协议层检测。
* 无订阅者时静默丢弃。

### 6002 下行帧（`RemoteCommandReceiver.h:29-82`）

```json
{"cmd":"action",
 "action":{"kLeftShoulderPitch.q":-0.206, ... 14 个手臂关节 ...,
           "remote.lx":0.0,"remote.ly":0.0,"remote.rx":-0.175,"remote.ry":0.0},
 "timestamp":1788514855.53}
```

校验规则（**任何一条不满足 → 整包静默丢弃**）：

| 规则 | 后果 |
|---|---|
| 必须有 `action`(map) 与 `timestamp`(数字) | 丢弃 |
| `timestamp` 必须**严格大于**上一条被接受的包 | 判为 stale，丢弃 |
| 关节键名为 `<LeRobot名>.q`，**按名字匹配、大小写不敏感** | 非手臂键被忽略（允许帧里带全身 29 个关节） |
| 每个值有限且 `abs(v) <= 3.2` | 丢弃 |
| **14 个手臂关节必须全部给齐** | 少一个 → 丢弃 |
| 单帧 ≤ 16384 字节 | 丢弃 |
| 摇杆轴映射 `vx=remote.ly, vy=-remote.lx, wz=-remote.rx`（`ry` 不用） | 缺失按 0 |

下发后的落地路径：`arm_q[slot] → motor_cmd()[15+slot]`，做 URDF 限位 + 每 1ms tick 限速
（`limits.velocity * 0.001`，FSM 线程 1kHz 合并发布唯一 LowCmd，推理线程 50Hz）。

**`--waist` 与 VLA 模式的注意点**：6002 只在机器人处于 **VLA 模式**（键盘 `3` / 手柄 `LB+A`）时才作用到手臂；
在 `Gamepad`/`Navigation` 模式下这些包会被接收并保存，但不会驱动手臂。切回 `Gamepad`（`LB+X`/键 `1`）时
手臂会按五阶 Bezier 平滑回到 `safe_home_q`。

## 目标流协议（本程序自己的 6003 端口）

| 端口 | 本程序侧 | 发送端 | 方向 | 内容 |
|---|---|---|---|---|
| **6003** | `PULL` bind `tcp://*:6003` | `PUSH` connect | 外部 → 本程序 | 目标位姿（JSON，最新优先） |

```json
{"pos":[0.33,-0.22,0.13]}                // 绝对位置（目标系, m；默认 torso_link）
{"delta":[0.005,0,0]}                    // 相对上一条目标的增量（一帧一次）
{"rpy":[0,0,0]}                          // 可选，不给则保持锁定的末端朝向
{"quat":[0,0,0,1]}                        // 可选：目标姿态四元数 (x,y,z,w)，不给则保持锁定朝向
{"arm":"right"}                          // 可选 right/left/both
{"pos_left":[...],"pos_right":[...]}     // 可选，一帧给双臂
{"timestamp":1788514855.53}              // 可选，仅用于诊断
```

* 语义：**最新优先**（积压丢旧帧，最多一次清 16 帧）；无新目标 → 保持上一条；非法帧丢弃并告警。
* `quat` 的优先级：**quat > rpy > 启动时锁定的末端朝向**；运行中敲 `r`（设 rpy）会清掉 quat。
  姿态由谁给：`tools/detect_aruco_zmq.py` 会算 `T_ee = T_marker @ [R_align | offset]` 并把位置+四元数一起发。
* 控制循环不受影响：无论有没有新目标，都会以 `--rate` 持续下发关节命令。
* `delta` 是"每帧增量"：连续发时等效速度 = delta × 帧率。所以 `pos/delta` 模式的发送工具默认**发一帧就退出**，
  避免一次调用把同一增量叠加多次。
* 实测：20 次 `delta=+5mm` 后目标 x 精确从 0.280 走到 0.380；circle 模式 30Hz 流式推送时手臂持续跟随。

## 上行广播：6004 夹爪状态 / 6000 控制模式（groot-control 2026-09-20 新增）

| 端口 | 上游侧 | 本程序侧 | 频率 | 内容 |
|---|---|---|---|---|
| **6000** | `PUB` bind | `SUB` connect | 50 Hz | 控制模式 `{"state":"vla"\|"nav"\|"gamepad"}` |
| **6004** | `PUB` bind | `SUB` connect | 100 Hz | 夹爪实测状态 `{"topic":"rt/dex1/state","data":{"right":{...},"left":{...}}}` |

```json
// 6000（ControlStateBroadcaster.h）
{"state":"vla"}

// 6004（GripperStateBroadcaster.h）：直接透传 DDS MotorStates_.states()[0]，**不做单位换算**
{"topic":"rt/dex1/state",
 "data":{"right":{"q":0.501,"dq":0.0,"tau_est":0.02},
         "left": {"q":0.500,"dq":0.0,"tau_est":0.02}}}
```

* 两个端口都**没有 ZMQ topic 前缀**（`topic` 是 JSON 字段）→ 必须 `subscribe(b"")`，与 6001 同一个坑。
* 夹爪 `q` 是**输出侧弧度**：`0`=完全闭合，上限是机器人侧标定的 `q_max`（默认 `5.6217 rad`＝322°）。
  桥接层不做"张开/闭合"语义换算，语义映射属于上位机。
* 夹爪电机 ID 顺序 **0=right、1=left**（右在前，与手臂"左臂在前"相反）。
* 本程序把这两人路当作"只读旁路"：显示在状态行（`夹爪=R0.50/L5.50 模式=vla`），
  **不是 vla 时限频告警**（手臂不会动的最常见原因）。收不到帧不影响任何控制行为。
* 离线验证：`python tools/mock_groot_status.py --mode vla --right 0.0 --left 5.5`。

### 下游（给夹爪发目标）——本工程已实现（`zmq_link.build_frame(gripper=…)`）

上游的做法是**复用 6002 action 帧里的可选 `gripper` 块**（不新开端口）：

```json
{"cmd":"action",
 "action":{"kLeftShoulderPitch.q":-0.20, ..., "remote.lx":0.0, ...,
           "gripper":{"right":{"q":0.0},"left":{"q":5.0}}},
 "timestamp":1788514855.53}
```

* 只读 `q`（弧度）；`kp`/`kd`/`mode` 的唯一来源是机器人侧 `config.yaml` 的 `FSM.Groot.gripper`，
  帧里传会被**忽略 + warn**。
* 量程超限是 **clamp 不丢帧**（先绝对限位再逐周期限速 `6.0 rad/s`，约 1.7 s 全行程）；
  手臂 `|q|>3.2` 仍整帧丢 —— 两条契约独立。
* 夹爪块非法只降级为"本帧不更新夹爪"，**手臂照常生效**；但 14 个手臂关节**仍然必填**。
* 桥接层 latch 后以 100 Hz **无条件重发**（`dex1_1_service` 有超时看门狗），所以**发一帧就够**。

### 力控只能在上位机做（`grip_control.SoftClose`）

上游的 6002 只接受 `q`（位置），**没有力/电流指令**，`dex1_1_service` 连范围都不校验，直接把
`q × gear` 发串口。所以：

* 把目标压到 `q_min`（全闭）时，伺服会持续用约 `kp × (指令 − 实际)` 的力顶着物体 —— 抓刚性盒子会压坏；
* 「夹到东西就停」只能由上位机闭环：读 6004 的 `tau_est`/`dq`，一边按限速推进目标、一边判断接触。

本工程的实现（`--grip-on-arrive-soft` / 交互 `gc` / 6003 的 `grip_close_tau`）：

| 环节 | 做法 |
|---|---|
| 逼近 | 目标 q 按 `rate_rad_s`（默认 1.5）往闭合方向推进 |
| 压紧 | `|tau| ≥ 30% × 阈值` 视为接触 → 换成 1/10 速度（0.15 rad/s）继续压，压小过冲（单向） |
| 退回 | 逼近是「盲走」（力反馈滞后一周期）：**第一次读到就超标**时先退回最后一次确认还没接触的实测位置，等 `|tau| < 5% × 阈值`（最多 20 周期）再慢压重试，每侧限 2 次 —— 否则实测会停在 3.3 倍阈值 |
| 冻结 | `|tau| ≥ 阈值` 立即冻结该侧（保持这个轻压紧力） |
| 次级 | 被挡住（实测比指令更张开）且 `|dq| < 0.02` 连续 4 周期、且 tau 始终低于接触阈值 → 目标停在「实测开口 − 1mm」，留 1mm 过盈轻夹持 |
| 安全 | 6004 超过 0.5s 无新帧 → 中止（没有力反馈不能力控）；恢复下发时 `reanchor()` |

实测（`tools/mock_gripper_box.py`，盒子 6cm、刚度 4 tau/cm）：

| 方式 | 指令停 | 接触过盈 | 稳态 tau |
|---|---|---|---|
| `g 0` | 0cm（全闭） | 6.0cm | **24.0**（夹坏） |
| `gc 0.3` | **5.92cm** | **0.80mm** | **0.31** ✓ |

本工程的接口（`--grip`/`--grip-right`/`--grip-left`、交互 `g R [L]`、6003 的 `grip`/`grip_rad`、
`--grip-on-arrive`）在发送前会把百分比/厘米换算成弧度并按 `--grip-qmin-rad/--grip-qmax-rad` clamp；
`build_frame()` 只在真有目标时才加这一块（**首个目标之前帧里没有 `gripper` 键**，与上游"静默等待首个目标"一致）。

## 已验证的结果（本机实测，G1-29DoF URDF）

### 9.1 CasADi + IPOPT（宇树原算法，`--solver casadi`）

环境：conda-forge `pinocchio 3.1.0` + `casadi 3.6.7`（与 xr_teleoperate 官方 requirements 一致）。

| 检查项 | 结果 |
|---|---|
| 正解一致性：CasADi 符号 FK vs Pinocchio 数值 FK | 最大逐元素差 **2.22e-16** ✓ |
| 原版误差 Function 在真值构型上的自残差 | **0.00 µm / 1.7e-14°** ✓ |
| 轨迹跟踪（`tools/selftest_offline.py --solver casadi --tracking`，半径 5cm 圆） | 位置残差 mean **2.07mm** / max 8.66mm，单帧 mean **8.6ms**（≈偏置量级，见下） |
| 正则偏置实测（同一批目标，各 10 组） | `w_reg=0.02`（原版）→ **3.045mm**；`w_reg=0` → **0.0015mm** ✓ |
| 目标大跳变 + 零位冷启动 | 30~40ms/帧（`max_iter=30` 跑满）；因此上真机前先 `--dry-run` 看 `ik_err` |
| 闭环（ZMQ 端到端，**默认 `--w-reg 0`**） | 6.4s 后收敛到 `ik_err` **0.1mm / 0.0°**，`track_err` 0.3mm，≈8ms/帧 @30Hz |
| 闭环（ZMQ 端到端，`--w-reg 0.02` 原版手感） | 收敛到 `ik_err` 2.4mm/0.4° |
| 闭环（ZMQ 端到端，`--w-reg 0`） | 收敛到 `ik_err` **0.5mm/0.1°** |

### 9.2 正则项：为什么默认从原版的 0.02 改成 0

原版代价里的 `0.02*||q||²` 会让解朝零位偏，带来两个可实测的后果：

**① 系统性位置偏置 ≈ 3mm。** 在真值构型 `q_true` 处整体代价并不为零（正则项贡献
`0.02*||q_true||² = 0.0499`），IPOPT 会主动用几毫米位置误差去换更小的正则代价 ——
实测 IPOPT 解的代价 0.048359 < 真值处的 0.049889，说明它确实找到了更优解，不是没收敛。
同一批目标实测：`w_reg=0.02` → 残差 **3.045mm**；`w_reg=0` → **0.0015mm**。

**② 静止保持时会缓慢漂移。** 因为平滑项锚定的是**本帧实测关节角**，而正则项往零位拉，
两者相互拉扯会让构型缓慢向零位爬。实测固定目标保持 120 帧（50Hz 下 2.4s）：

| 权重 | q 最大漂移 | 肘关节漂移 | 最终末端残差 |
|---|---|---|---|
| `--w-reg 0`（本工程默认） | **0.0004 rad** | 0.00005 rad | **0.0007 mm** |
| `--w-reg 0.02`（原版） | 0.2635 rad | 0.0525 rad | 2.389 mm |

**③ `--w-reg 0` 不会让冗余自由度失控**：零空间锚定由平滑项 `0.1*||q-q_ref||²` 承担，
`q_ref` 是实测角，等价于"停在当前构型"，比原版"朝零位拉"更可预测（上面第①行就是证据）。

所以默认取 0（精度优先）。**要复现 xr_teleoperate 原版行为/手感，加 `--w-reg 0.02` 即可**
（常数也留在代码里：`g1_ik.W_REGULARIZATION_UNITREE`）。

> 如果伺服滞后明显，还可以再试 `--ik-smooth-ref previous`（平滑参考量改成上一帧下发值）：
> 闭环实测 `ik_err` 0.0mm，比默认的 `measured`（0.2mm）更贴目标，代价是丢掉了原版
> "贴着实测角" 的那层保护。

### 9.3 DLS 回退求解器（`--solver dls`，仅在缺 CasADi 时用）

`python tools/selftest_offline.py --tracking`：

| 检查项 | 结果 |
|---|---|
| 腰部换算与全模型 FK 的一致性 | 逐元素最大误差 **1.5e-16** ✓ |
| 反解精度（从扰动位姿热启动，= 正常跟踪工况） | 位置 **≤0.094mm**，姿态 **≤0.043°**，0.13ms/次 |
| 反解精度（从零位热启动，= 最严苛） | 位置 ≤3.3mm，姿态 ≤1.0°（目标跨度 ±1.2rad 的极端随机位姿） |
| 轨迹跟踪（目标沿 x-z 圆 5cm 连续移动） | 位置残差 **max 0.010mm**，0.05ms/次 |
| 关节限位 | 全部满足 ✓ |

`tools/mock_robot.py` + 真 ZMQ 链路的端到端实测：

| 检查项 | 结果 |
|---|---|
| 6001 订阅（`subscribe(b"")`） | 稳定收帧 ≈390~500Hz，解析无坏帧 |
| 6002 下发 → 假机器人跟随 | 右臂收敛到目标，`track_err = 0.0mm` |
| 协议拒绝规则（4 种坏帧） | `stale timestamp` / `expected 14 arm joints (got 13)` / `joint value out of range` 全部按 C++ 规则丢弃 ✓ |
| 非零腰角下的坐标换算 | `--waist state` 收敛到目标（0.0mm）；`--waist zero` 如实报出 134.3mm 偏差 ✓ |
| `--arm both` | 两臂同时到位，各自 `track_err = 0.0mm` ✓ |
| `--delta` 相对位移 | 前移 (0.06,0.03,0) 后精确到位 ✓ |
| `--interactive` | `p`/`d`/`a left` 均即时生效；切臂后右臂冻结保持 ✓ |
| **状态超时保护** | 中途杀掉状态源后：`状态超时 655ms -> 不下发`，之后不再发送（300 周期只发了 107 帧）✓ |

> DLS 的末端残差比原算法更小（亚毫米），是因为它**只把末端误差当主目标**，对关节空间只有很弱的
> 零空间牵引，而原算法完整包含 `0.02*||q||²` 正则项（就是上面那 3mm 偏置的来源）。
> 所以"残差更小"不等于"更正确" —— **要复现宇树的行为就用 `--solver casadi`**。

上面这些数字说明：链路、关节序、坐标换算、协议约束、安全兜底都是对的；换到真机只需要改 IP 和模式。

> **关于 `--demo circle` 的 `track_err`（≈50~80mm）**：这不是控制器的问题，而是假机器人/仿真的
> 手臂只是"一阶滞后 + 2 rad/s 限速"的粗糙模型。半径 6cm、周期 4s 的圆需要肘关节 0.92 rad/s，
> 一阶滞后的稳态误差 = v·τ = 0.92×0.1 = **0.092 rad**，实测假机器人滞后 **0.099 rad**，完全吻合；
> 而这 0.1 rad 的肘关节滞后在机械臂几何上放大成数厘米的末端偏差。同一时刻 `ik_err` 只有 2mm，
> 说明**求解器跟得上移动目标**。真机上是 1kHz PD 伺服，滞后由 Kp/Kd 和 URDF 速度上限决定，
> 用 `track_err` 就能直接读出真实跟随性能。

### 9.4 到位判定（本工程新增，`arrival.py`）

判据设计见 README §5。下面是在**本机 `--sim`（一阶跟随模型）**上跑出来的实测数据，
用来说明每条判据的取值是否合理（不是真机数据，真机的伺服滞后会让耗时变长）。

| 检查项（命令） | 结果 |
|---|---|
| 静态目标，单臂，`--solver casadi`（默认） | 到位耗时 **1.72s**，到位时 `track_err` **0.99mm / 0.22°**，驻留 0.22s ✓ |
| 静态目标，单臂，`--solver dls` | 到位耗时 **1.29s**，`ik_err`/`track_err` 均 **0.1mm** ✓ |
| 双臂 `--arm both --pos-left … --pos-right …` | 两臂**各自独立**判定：left 0.42mm/0.09°、right 0.83mm/0.18°，耗时同为 1.81s ✓ |
| 不可达目标 `--pos 1.20 -0.20 0.50` | 3.0s 时给出一条 `⏱ 未到位`：`ik_err` **785.2mm / 13.96°**，状态行一直 `✗不可达`，手臂停在能到的最近处 (0.426,-0.170,0.370) ✓ |
| 轨迹 `--demo circle`（半径 5cm / 周期 6s） | 5s 内 **0 次**到位 —— 判据④（末端速度 ≤15mm/s）拦住了"路过"式假到位，状态恒为 `✗跟随中` ✓ |
| ZMQ 目标流重复下发同一条目标（30Hz × 130 帧） | 目标计数 = **1**（不被当成新目标），驻留计时不被清零，仍能判出到位 ✓ |
| `--on-arrive freeze` + 目标流 | 到位后流里的**新**目标被丢弃（手臂不动、不产生到位事件）；交互 `p` 解冻后按新目标再次到位 ✓ |
| `--on-arrive exit` | 1.43s 到位即退出（`--duration 10` 未生效）✓ |
| `tools/test_arrival.py`（合成 StepInfo，13 个场景） | **40/40 通过**：正常到位 / 驻留不够 / 高速路过 / 不可达 / 被挡住 / 限位 / 状态超时 / 滞回离开 / 目标变更 / 流式重复 / 无显式目标 / 关节零空间漂移 / 限速瞬态不误报 ✓ |

> **瞬态不误判**：`--max-step-deg 2.0` 限速追赶时 `ik_err` 会瞬时很大（实测 115mm），
> 这时状态行显示 `✗跟随中` 而不是 `✗不可达` —— "不可达 / 被挡住"只在**末端停稳**
> （速度 <1mm/s 且距目标变更超过 2×dwell）之后才下结论。
>

> `_pending_position` 里，左臂的目标会被右臂覆盖 → 左臂目标丢失。现在按手臂排队
> （`_pending_positions`），双臂启动时都能拿到各自的目标。

## 常见问题

**收不到状态帧（`尚无状态帧` / `state_age` 一直涨）**
1. 机器人是否已进入 `Groot` 状态（端口在 `enter()` 里才 bind）；
2. `ping <机器人IP>`，是否同网段；
3. 机器人上 `ss -lntp | grep 600` 看端口是否在监听；
4. 订阅前缀必须为空 —— 代码里是 `subscribe(b"")`，**线上没有 ZMQ topic 前缀**，
   写成 `subscribe(b"rt/lowstate")` 会一个字节都收不到。

**发了指令手臂不动**
机器人不在 VLA 模式（键 `3` / `LB+A`）。另外检查 `send_test.py` 的四种坏帧是否被你复现了
（timestamp 不递增、少关节、超范围都会被静默丢弃）。

**末端到不了目标 / 一直有 `track_err`**
1. 目标不可达 → 状态行写 `✗不可达`，并会提前打一条
   `⛔ 目标不可达 [右臂] 反解残差 Xmm/Y° ...`（每个目标一次，比 `--arrive-timeout` 早，
   里面直接写了反解/实测残差和是否顶到限位）。注意旧版本会把它误报成 `✗跟随中（伺服滞后）`
   —— 那是因为"停稳"的速度门槛（1mm/s）比真机停稳后仍在微调的速度（~1.5mm/s）还严；
2. 腰角非零但用了 `--waist zero` → 看 `[腰未参与换算, 偏差Xmm]`（状态行是 `✗跟随中`）；
3. `--max-step-deg` 太小、`--rate` 太低 → 跟随速度跟不上目标移动（`✗跟随中` + `限速 N 个关节`）；
4. 停稳了但差一点点（`✗临界未达`）→ 判据过严或存在稳态误差，用 `t 5 2` 放宽，或查 `--w-reg`。
   注意 `t` 放宽会受限：位置容差到物体窄边、姿态到 45° 就会被护栏拒（见 `--arrive-object-mm`）。

**跟踪抖动**
保持 `--no-filter` 关闭（默认开启加权滑动平均），或把 `--rate` 提高到 100Hz；
IK 权重里的 `0.1*||q-q_last||²` 平滑项已经在抑制抖动，不要随意改小。

**IK 太慢**
默认 `max_iter=30`；`--ik-max-iter 15` 可以更快但精度下降。DLS 回退一般 0.1~0.7ms/次，比 IPOPT 快。

**换了机型/URDF**
`joint_map.py` 的 29 关节表是按 G1-29DoF 写的（电机序 0..28，手/夹爪不在其中）；
换机型要同步改 `joint_map.py` 的关节表。
换**末端变体**（Dex3 三指手 ↔ Dex1 夹爪）**不需要改代码**：`g1_ik.py` 会从 URDF 自动推导
"要锁定的关节"（= 除 14 个手臂关节以外的所有可动关节），只需 `--urdf` 指到对应文件、
`--ee-offset` 给出末端点偏移。已实测的两种变体见 README §3.1。

## 与原版 xr_teleoperate 的差异（完整清单）

| 项 | 原版 | 本工程 |
|---|---|---|
| IK 算法与权重 | CasADi + IPOPT，50/1.0/0.02/0.1 | **完全一致**（`--solver casadi`） |
| 平滑滤波 | `[0.4,0.3,0.2,0.1]` 加权滑动平均 | 一致 |

| 力矩 | `pin.rnea` 算重力补偿并下发 | **去掉**（6002 协议无 tau 字段） |
| 腰关节 | 锁死在 0 | **可选**用实测腰角做坐标换算（`--waist state` 默认；`zero` 时与原版等价） |
| 目标来源 | XR 头显手部姿态 | 命令行/交互/内置轨迹（也可自己接 XR） |
| 下发力矩/位置 | DDS `motor_cmd.q/tau` | ZMQ 6002（JSON，14 关节名值对） |
| 可视化 | meshcat + 200MB meshes | 无（改为打印 `meas/tgt/ik_err/track_err` 数值） |
| 力矩/速度前馈 | 有 | 无（协议不支持） |
