两个问题：

1. 7-DOF 机械臂根据目标位置反解之后，规划轨迹的方法都有哪些？
2. 当前代码库（`g1_zmq_ik`）中的轨迹是如何规划的？

# 第一部分：方法调研

## 0. 先把「三层」分清（不然讨论会一直串味）

反解只给出一个**稳态映射** `q = IK(T_target)`。轨迹规划要回答的是"从当前构型走到那个构型的
中间每一拍给什么"，它同时包含三层，工程上必须分别选：

| 层 | 决定什么 | 典型选项 |
|---|---|---|
| **① 路径层（几何）** | 末端或关节在空间里走什么形状 | 关节空间 PTP / 笛卡尔直线 / 圆弧 / 样条 / 采样式规划出的折线 |
| **② 时间律层（调度）** | 沿这条路径怎么分配时间 | 梯形速度 / S 形（jerk 限幅）/ 多项式 / B 样条 / 时间最优参数化 TOPP |
| **③ 伺服层（逐拍执行）** | 每拍把位姿变成关节角 | 每周期整段反解（带热启动）/ 雅可比伪逆速率控制 / 逆动力学力矩控制 |

绝大多数"方法之争"其实是**③ 选了哪一类**。本代码库选的是"① 默认无路径 + ② 只有 LIN 段有显式
时间律 + ③ 每周期整段 IK 反解"。

## 1. 关节空间插值（PTP / moveJ）：每个路点先反解，再在关节空间插值

**做法**：对起点和终点各做一次反解得到 `q0, q1`，然后在关节空间插值 `q(t)`。

- 三次多项式：给定 `q0, q1, q̇0=q̇1=0`，加速度在两端有阶跃。
- 五次多项式：同时给定两端速度与加速度，加速度连续，是最常用的"平滑 PTP"。
- B 样条 / 梯形速度 + 抛物线过渡：`q(t)` 的速度是梯形，加速度不连续（jerk 无穷）。
- S 形（jerk 限幅）曲线：加速度本身也连续，起停无冲击，工业上"最舒服"的默认。

**优点**：计算极便宜、无需逐拍反解、天然不会在奇异点附近发散。

**缺点（决定性）**：**关节空间直线 ≠ 笛卡尔直线**。末端走的是关节空间直线在正解映射下的像，
是一条弧（大口径圆弧或更复杂的曲线），会撞到中间障碍物。而且**弧的形状取决于你选了哪个
IK 分支**——起点解和终点解选到不同的肘部构型，末端可能划出一条完全不同的路。

**适用**：自由空间里长距离转移（不关心路径形状，只关心快和稳）。

## 2. 笛卡尔路径 + 逐拍反解（moveL / Cartesian servo）

**做法**：先定义笛卡尔路径（线段/圆弧/样条），再沿它按时间采样出位姿序列 `T(s(t))`，
每一拍对当前位姿解一次反解。

- 位置：`p(s) = p0 + s·(p1 − p0)`（直线），或圆弧/螺旋线。
- 姿态：轴角 / 四元数 SLERP / 测地线插值 `R(s) = R0·exp(s·log(R0ᵀR1))`——**不要用欧拉角线性插值**，
  会有万向锁和角速度不连续。
- 时间律：梯形（速度+加速度）或双 S（速度+加速度+jerk 限幅）。工业控制器的 `moveL` 都有
  这两档。
- 闭环 vs 开环：开环=算好整条曲线再喂；闭环=每拍用实测位姿修正剩余路径（更难但抗扰动）。

**优点**：路径可预测、可验证（可以离线量直线度）、便于避障检查。
**缺点**：每拍一次反解 → 实时预算吃紧；接近奇异点时反解残差变大、关节速度爆掉；
路径如果穿过不可达区，会在中途卡住。

**工业对标**：`moveL`。本代码库的 `LinearMove` 就属于这一族，只是它把"路径"限定成
"沿工具轴的直线段"。

## 3. 微分/速度层控制（resolved-rate 家族）

不在位姿层反解，而在**速度层**闭环：

| 方法 | 公式 | 说明 |
|---|---|---|
| Resolved-Rate | `q̇ = J⁺ ẋ` | 最基础；J 奇异时爆炸 |
| Damped Least Squares (DLS / Levenberg–Marquardt) | `q̇ = Jᵀ(JJᵀ + λ²I)⁻¹ ẋ` | 用阻尼 λ 换掉奇异点附近的爆炸；λ 可按最小奇异值自适应 |
| Singularity-Robust Inverse (SRI) | 用滤波后的奇异值 `σ/(σ²+λ²)` | DLS 的 SVD 形式，可只对"小的"奇异值加阻尼 |
| Resolved Acceleration Control (RAC) | `q̈ = J⁺(ẍ − J̇q̇)` | 二阶；加速度层闭环 |
| Task-Priority / Null-Space Projection | `q̇ = J₁⁺ẋ₁ + (I − J₁⁺J₁)J₂⁺(ẋ₂ − J₂J₁⁺ẋ₁)` | 主任务不变的前提下做次级任务 |

经典来源：Khatib 的 operational space 框架；Nakamura & Hanafusa 的可操作度椭球；
Wampler 的 DLS；Chan & Dubey 的 SRI；Liégeois 的梯度投影。

**优点**：实时性极好（一次矩阵求逆），天然支持"边动边改目标"（移动目标跟踪、遥操作）。
**缺点**：只是**局部**方法，没有路径概念，会被局部极小（如肘部死点）卡住；
需要显式地、逐拍地处理限位（一般是把限位转成关节速度约束加进 QP）。

## 4. 冗余分解——7-DOF 的核心（这是 7 轴和 6 轴的本质区别）

7-DOF 对一个 6 维任务有 **1 维零空间（自运动流形）**：末端不动，整条臂可以绕
"肩–腕连线"这根轴转一圈，肘部画圆。所有"7 轴规划"的高级技巧都在用这 1 维自由度。

**(a) 参数化法（闭式 / 解析）**
把零空间参数显式化——最经典的是**臂角 / 肘部角（swivel angle, arm angle）**：
给定腕心位置，7-DOF 臂的肘部位置落在一个圆上，用角度 `ψ` 参数化。
于是 `q = f(T_target, ψ)` 有闭式解，规划就变成"规划一条 `ψ(t)` 曲线"。
优点：完全可预测、无迭代、天然连续（只要 `ψ(t)` 连续）；缺点：只对有特定几何
（肩 3 轴交于一点 + 球形腕）的臂成立，G1 这类臂不能直接套。

**(b) 零空间优化（局部）**
在零空间里最小化某个标量势函数：
- **可操作度**（Yoshikawa：`w = √det(JJᵀ)`）最大化 → 远离奇异；
- **到关节限位的距离**最大化 → 避免顶死；
- **关节力矩 / 能量**最小化；
- **避障**势场（与最近障碍距离的倒数）；
- **朝参考构型靠拢** `‖q − q_ref‖²` —— 最简单的"锚定"，用来压制冗余漂移。

做的方式：`q̇ = J⁺ẋ + (I − J⁺J)·k·∇h(q)`（梯度投影），或直接把 `h(q)` 作为代价项塞进
优化问题里（本代码库走的是后者）。

**(c) QP / 分层 QP（现代主流）**
把"任务 + 限位 + 限速"统一写成一个二次规划，带不等式约束：

```
min  ‖J q̇ − ẋ‖² + w‖q̇‖²
s.t. q̇_min ≤ q̇ ≤ q̇_max          （由 (q_max − q)/dt 等推出）
     (可选) A_obs q̇ ≤ b_obs     （避障一阶近似）
```

多任务时用**严格分层**（hierarchical QP / HQP）：第一层解出后把它的零空间投影出来，
第二层在其上求解，逐层往下。求解器一般用 OSQP / qpOASES / ProxQP，1 kHz 也跑得动。
比"加权求和"的好处是**优先级严格**——不会出现"为了小任务牺牲大任务"。

**(d) 全局优化**
把整条 `q(t)` 或整条 `ψ(t)` 当成优化变量，全局地优化可操作度/避障/平滑度——属于下面第 5 类。

**7-DOF 冗余的工程价值**：能绕开奇异、能在受限空间（窄缝、机舱、人形机器人胸前）
把肘部甩到一边、能同时满足末端任务与肘部避障。这是 7 轴机械臂存在的主要理由。

## 5. 轨迹优化 / 最优控制

把整条轨迹 `q(t)` 当成优化变量，最小化"平滑度 + 障碍代价 + 时间"，比局部方法全局。

| 方法 | 思路 |
|---|---|
| **CHOMP** | 用协变梯度下降优化整条轨迹，障碍用符号距离场的积分代价，平滑项用加速度平方积分 |
| **STOMP** | 无梯度随机采样（类似 PI²），不要求代价可微，能穿过噪声代价 |
| **TrajOpt** | 序列凸优化（SCP）：把非凸避障约束线性化，反复解 QP，收敛快、工业界用得多 |
| **GPMP / GPMP2** | 把轨迹当成高斯过程的一条采样，用因子图（GTSAM）做 MAP 推断，天然给出不确定性 |
| **DDP / iLQR / Crocoddyl** | 差分动态规划，适合带动力学约束（力矩层）的最优控制 |
| **直接配点 / 直接打靶** | 把连续最优控制离散成 NLP，交给 IPOPT / SNOPT |

**和反解的关系**：实际系统里常见"**先用 IK 生成一个大致可行的初始轨迹，再用上面这些
方法做局部优化**"——即 IK 提供 warm start，轨迹优化负责避障与平滑。

**优点**：能真正避障、能全局考虑。**缺点**：非凸、求解时间不确定（几十 ms 到几秒），
不适合硬实时的伺服环；通常作为"离线/秒级重规划层"。

## 6. 时间最优路径参数化（TOPP / TOPP-RA）

给定一条几何路径 `q(s)`（或笛卡尔路径），求时间律 `s(t)`，使总时间最短且满足
速度/加速度/力矩约束。核心是把约束化成对 `s` 和 `ṡ` 的约束，在 `(s, ṡ)` 相平面上做
**可达性分析（reachability analysis）**：

```
ṡ² 的上界  = min over 约束
ṡ²(s) 沿路径的传播：用"最大可达速度曲线"从两端迭代
```

经典是 Bobrow 的 MVP 算法，现代实现是 **TOPP-RA**（Pham & Pham，基于可达性分析，
有开源实现，ROS 里有 `roboplan_toppra` 等封装）。比固定梯形/S 形曲线的优势是：
**非对称限幅、任意路径、真正的全局时间最优**。

## 7. 采样式运动规划（有障碍物时的必经之路）

| 算法 | 特点 |
|---|---|
| RRT / RRT-Connect | 快速探索，速度快，路径质量差 |
| RRT* / Informed RRT* | 渐进最优，慢 |
| PRM / PRM* | 多查询，适合固定环境 |
| BiTRRT / LBKPIECE | OMPL 里更实用的默认选择 |

**7-DOF 如何被利用**：规划在**关节空间**（14 维或 7 维）里做，所以 1 维冗余直接变成
"多一条能绕开障碍的通道"；终点通常用 IK 求出若干候选解，作为规划的 goal set。
工程栈：**OMPL + MoveIt**（ROS 生态的标准答案）。MoveIt 的流水线就是
"IK 求终点 → 关节空间采样规划 → 时间参数化（TOTG / Iterative Parabolic）→ 控制器执行"。
IK 插件常用 **TRAC-IK**（并行跑 KDL 与 SQP 两种求解器，谁先收敛用谁）或 **BioIK**
（把限位、可操作度、避障都写进一个进化优化目标）。

**优点**：只要解存在就大概率能找到，能真正避障。
**缺点**：耗时长（10 ms~1 s）、路径抖、不保证平滑、不适合伺服环内。

## 8. 最小 jerk / 最小 snap 轨迹

Flash & Hogan 的最小 jerk 模型（`min ∫ ‖d³x/dt³‖²dt`，解是五次多项式）源于人类
手臂运动研究，现在广泛用于人形/协作臂的点到点运动：给定起止位姿和总时长 `T`，
直接给出解析的 `s(t)`，起停平滑、无过冲。最小 snap 是它的四阶推广（无人机常用）。

**优点**：闭式解、极平滑、时长可调可预测。**缺点**：需要预先知道 `T`（或假设限幅），
对动态变化的目标不适用——所以通常用在"离线段规划 + 在线重规划"的外层。

## 9. 学习类方法

- **Diffusion Policy / 轨迹扩散模型**：把整条动作序列当成一个分布去采样，多模态（同一
  目标可以有多种抓取路径），近年 VLA 里很热。
- **Motion Planning Transformer / 学习式规划**：从大规模规划数据集里学"给定起点终点
  直接输出路径"，推理比采样快几个数量级。
- **学习式 IK + RL 微调**：神经网络给 IK 初值，再用 RL 微调避障/限位。
- **模仿学习 + 残差控制**：经典控制器保证安全，学习模块只输出残差。

**现状**：在**反解之后**这一段，学习类方法主要用于"生成初值/候选"或"在多模态里选一个"，
真正下发到电机的那一层仍然是经典控制（限幅、限位、IMU/力矩反馈），因为可验证性是硬要求。

## 10. 工程上一定要处理的几件事

**(1) 连续两拍的反解解必须连续（IK 分支连续性）**——这是实际系统里最容易翻车的地方。
手段（按可靠性排序）：

1. **用上一拍解/本拍实测角热启动**（warm start）——最有效，绝大多数情况下自然落在同一分支；
2. **在代价里加"朝上一拍解靠拢"的正则项** `w‖q − q_prev‖²`——把连续性变成软约束；
3. **显式分支检查**：算出多个 IK 解，按 `‖q_new − q_prev‖` 最小者选；
4. **参数化法**（第 4(a) 条）：用臂角 `ψ` 参数化后，`ψ(t)` 连续就保证分支连续——
   这是唯一**有保证**的做法；
5. **关节空间限速 + 抖动检测**：作为最后一道兜底。

**(2) 限位与限速**：关节位置约束要做成**硬约束**（进优化问题/NLP），不能只靠事后 clip——
事后 clip 会让路径偏离预期（这是本代码库要"直线段退一拍"的原因）。
速度/加速度/jerk 限幅则通常在增量层做。

**(3) 奇异点**：DLS/SRI 的阻尼、可操作度最大化、或直接避免规划经过奇异构型
（腕部奇异：腕心落在肩–肘轴上；肩部奇异：腕心落在肩关节轴上）。

**(4) 实时预算**：伺服环 1 kHz 时只能用 DLS/QP（微秒级）；50~100 Hz 的整段 NLP 反解
（毫秒级）是可行但紧张的；采样规划和轨迹优化只能放在更外层（几十 ms 到秒级）。

**(5) 腕部振荡**：多来自"姿态误差权重远小于位置误差权重"+"没有低通滤波"+"限速不连续"，
标准解法是姿态误差用 `log3` 而不是欧拉角差、加低通/滑动平均、加 jerk 限幅。

## 11. 选型决策指南

```
末端路径形状重要吗？
├─ 不重要，只要快、稳、别撞 → 关节空间 PTP（五次多项式 / S 形曲线）
└─ 重要（插装、抓取、涂胶、焊接）
   ├─ 环境自由、只有目标位姿 → 笛卡尔路径 + 逐拍反解（moveL），
   │     姿态用 SLERP/测地线，时间律用 S 形
   └─ 有障碍物 → 外层用采样/优化规划（OMPL/CHOMP/TrajOpt）出关节空间路径，
         内层用时间参数化（TOPP-RA）+ 逐拍反解或 DLS 执行

需要边动边改目标（遥操作 / 视觉伺服 / 移动目标）吗？
└─ 是 → 速度层闭环（resolved-rate / DLS）+ 限位 QP；不要用离线规划

是 7-DOF 且需要避开奇异 / 肘部避障 / 受限空间吗？
└─ 是 → 显式利用零空间：臂角参数化（有闭式时）或零空间优化 / HQP
     （可操作度、限位距离、避障），别让它自己漂

反解分支会跳吗？（连续两拍解差异大）
└─ 会 → 热启动 + 正则项 + 分支检查；有闭式臂角解时优先用参数化
```

# 第二部分：本代码库的轨迹规划实现

## 2.0 一句话概括

**本代码库默认不做"轨迹规划"——它做的是"逐周期全位姿反解 + 多重限幅"，轨迹是闭环涌现出来的；
显式打开直线模式后才在笛卡尔空间里走直线：`--lin-approach/--lin-retreat` 只在最后的抓取进给/退出段
走直线，`--lin-all` 则把整段移动按 Z→Y→X 拆成若干轴对齐直线段（段间角点停，详见 §2.4）。**

数据流（`controller.py` 文件头注释，与实际代码一致）：

```
6001 状态 ──▶ q14_meas/q_waist3 ──▶ FK ──▶ 当前末端位姿(torso 系)
                                              │
目标(torso 系) ──▶ [LIN 插值出路点] ──▶ IK ──▶ q_raw
                                              │
                        加权滑动平均 ──▶ 冻结非受控臂 ──▶ 关节限速 ──▶ 笛卡尔限速/限加速/限jerk
                                              │
                                        URDF 限位 clip ──▶ 6002 下发
```

**控制周期**：`--rate` 默认 **50 Hz**（`dt = 20 ms`，`main.py:892`）。

## 2.1 目标从哪里来（三条并行入口，都写进同一个 `self.target`）

| 入口 | 代码 | 说明 |
|---|---|---|
| 命令行静态目标 | `--pos/--pos-left/--pos-right/--rpy/--quat/--delta` → `set_target_position` / `set_target_rpy` / `move_target_by` | 启动时给一次 |
| 进程内演示轨迹生成器 | `DemoTrajectory`（`main.py:537`），`--demo circle‖line` | **每个周期**根据 `elapse` 重算目标：circle = 在 x-z 平面画圆（左臂反向以对称）；line = 沿 x 往返。圆心/起点在第一个周期由当时**指令位姿**的 FK 位置确定 |
| 外部 ZMQ 6003 目标流 | `TargetReceiver` + `apply_stream_target`（`main.py:448`） | 支持 `pos`（绝对）/`delta`（相对上一条目标叠加）/`per_arm`/`pos_left`/`pos_right`/`rpy`/`quat`/`arm`。**最新帧优先**，积压的旧帧被丢弃 |

**姿态的来源优先级**（`make_target_pose`，`controller.py:510`）：
`quat` > `rpy` > **启动时锁定的参考姿态** `_ref_rot`。
只发位置的流（配置里 `send_quat=false`）会让末端**保持启动瞬间的朝向**——
所以 README 强调"启动 `main.py` 时要让手臂处于你想要的进给姿态"。

**目标变更的判定**（`_assign_target`，`controller.py:485`）：
位置差 `> 1e-4 m` 或旋转矩阵逐元素差 `> 1e-4` 才算"变了"，`target_rev` 才自增。
这是为了不让 20~30 Hz 重复下发的同一条目标反复清零到位判定的驻留计时。

## 2.2 目标 → 路点：`_ik_targets` + `_advance_lin`（`controller.py:883 / 670`）

每个周期有两个位姿概念，**必须分清**：

- `T_*_tgt` = **用户目标（终点）**——到位判定、制动距离都用它；
- `T_*_wp` = **本周期真正喂给 IK 的位姿**——有直线段时是插值出来的路点，否则就是终点。

```python
T_L_tgt, T_R_tgt = self._ik_targets(T_L_meas, T_R_meas)   # 目标系 -> 求解系(torso)
T_L_wp,  T_R_wp  = self._advance_lin(dt, T_L_tgt, T_R_tgt)
q_raw = self.ik.solve(T_L_wp, T_R_wp, self.q_meas)
```

`_advance_lin` 的三种情形：

1. **无直线段、无待接近** → `T_wp = T_tgt`（**纯 PTP 语义：每拍都直接追最终目标**）；
2. **有待接近（第一段）** → `T_wp = T_tgt`（= pre-grasp）；当**指令位姿**到 pre-grasp 的距离
   ≤ `lin_reach_tol = 5 mm` 时，自动 `start_linear` 切到第二段，本拍喂线段起点；
3. **直线段进行中** → `T_wp = mv.advance(dt)`（时间推进后的路点）；走完就置 `None`。

## 2.3 默认模式：没有显式轨迹，轨迹是"闭环涌现"的

`--lin-approach` 默认 **0（关闭）**。此时每个周期 IK 都被喂**同一个最终目标**，
所以"轨迹"完全由下面这条链决定：

```
最终目标 T_tgt
  └─▶ 每周期整段 IK（带热启动 + 平滑代价项）  ──▶ q_raw      ← 求解器内部迭代，不是时间律
        └─▶ 4 抽头加权滑动平均                      ──▶ q_new   ← 时间平滑（唯一的时间维度）
              └─▶ 冻结非受控臂
                    └─▶ 关节增量限幅（2°/拍）
                          └─▶ 笛卡尔速度/加速度/jerk 钳制（全局 scale）
                                └─▶ URDF 限位 clip
                                      └─▶ q_send 下发 6002
```

**关键推论（README §4 也明说了）**：末端走的是**关节空间最短路径在正解映射下的像**，
在笛卡尔空间里是一条**弧**，不是直线。这不是缺陷而是设计取舍：
长距离转移用 PTP 快、不易在奇异点附近失败，只在真正需要直线的最后一段（抓取进给）
才用 LIN。

`tools/audit_motion_path.py` 就是专门量这件事的：它把每拍下发的末端位置连成"路线"，
再算每一点到"起点→终点弦"的**垂直距离**，给出 `max_dev / mean_dev / path_len / chord_len`。
开了 LIN 之后它按段分开量（PTP 段不管，只看 LIN 段的偏离）。

## 2.4 LIN 模式：`LinearMove` —— 本库唯一的显式轨迹生成器

代码：`controller.py:83-284`（`@dataclass LinearMove`）。它是整个库里最"标准"的轨迹规划器。

### (a) 几何：位置直线 + 姿态测地线

```
p(s) = p0 + s·(p1 − p0)                       # 直线，s ∈ [0,1]
R(s) = R0 · exp( s · log(R0ᵀ R1) )            # SO(3) 测地线，等价 SLERP，无万向锁
```

`_rot_log` / `_rot_exp` 是自己实现的 SO(3) 对数/指数映射（`controller.py:62-80`），
对数映射在 0°/180° 附近做了有限性兜底。

### (b) 时间律：预先规划、后采样（不是逐拍跟踪）

时间律在 **1 ms 细网格**上一次性积分出来（`LIN_PROFILE_DT = 1e-3`），之后 `np.interp` 采样。
代码注释解释了为什么不逐拍跟踪制动包络：包络自己会随剩余距离收缩，实际速度一旦超过包络，
包络下降得比 `-a` 还快，就再也追不回来（到终点停不住）。

构造三段式：

1. **加速段**：用 `ramp(v_to)` 积分。采用"三段式判据"而不是逐点跟踪锥形律——
   jerk 下降段能覆盖的速度增量恰好是 `Δv = a²/(2·u_j)`，所以**当剩余速度增量等于它时
   就开始收加速度**，加速度以 jerk `u_j` 线性降到 0 的同时速度正好落在 `v_to`。
   进入收加速度段后**粘住**不再回头（避免判据两边的浮点抖动）。
2. **二分找峰值** `v_peak`：使 `2·d_accel(v_peak) ≤ 1`（60 次二分），即"恰好能在总距离内停下"。
3. **曲线 = 加速段 + 匀速段 + 加速段的镜像**。

因为是精确镜像，**终点速度精确为 0、进度精确到 1，且速度/加速度/jerk 三条限幅同时成立**。
`j_max = 0` 时退化成梯形曲线；`j_max > 0` 时是 S 形曲线。

### (c) 单位换算：把"平移 + 旋转"折成一个标量进度

```
L_lin  = ‖p1 − p0‖                          # 直线长度
Δθ     = ‖log(R0ᵀR1)‖                       # 转角
scale  = max(L_lin, Δθ · 0.15)              # LIN_ROT_RADIUS = 0.15 m（腕到指尖的尺度）

u_v = min(v_max / L_lin, w_max / Δθ)        # 速度上限（s 的单位：1/s）
u_a = a_max / scale
u_j = j_max / scale
```

于是**位置和姿态共享同一条 `s(t)`**——这是标准的"路径参数化 + 同步运动"，
而不是分别给平移和旋转各做一条时间律。

⚠️ 一个可以改进的点：LIN 段只有 `--lin-rot-speed`（角**速度**上限），
**没有** `lin_rot_accel / lin_rot_jerk`。角加速度/角 jerk 只通过共享标量曲线的
`scale` 被间接约束，不是独立限幅的。

### (d) 确定性 + 可回退

- 同样的 `dt` 序列 → 同样的轨迹，**可离线单测**（`tools/test_cartesian_lin.py` 验证
  直线度 ~1e-12、姿态插值、三条限幅、闭环跟踪、IK 失效即停、到位判据、两段式接近 7 项）。
- **对控制周期抖动免疫**：积分网格与控制周期解耦。
- `rollback()`：把 `t` 退回上一次 `advance` 之前——**IK 失败或关节被限速时，
  路点不许跑在手臂前面**。

### (e) 两段式接近 / 退出（抓取专用）

- `start_approach(arm, T_grasp, approach_dist)`（`controller.py:596`）：
  `pre-grasp = 抓取点 − d · x̂_tool`，其中 `x̂_tool` = 目标姿态旋转矩阵的**第 0 列**
  （工具轴 = 夹爪进给方向）。长距离转移仍走 PTP（快、不易撞），只有最后 `d` 是直线。
- `retract(arm, distance)`（`controller.py:637`）：沿当前工具轴反方向直线退出
  （抓完把物体拉出来）。
- **幂等性处理**（很实用的一处工程细节）：Tag 目标流以 20 Hz 重发同一条目标，
  如果每次都重启状态机，直线段会被每 50 ms 打断一次——实测被打断 259 次、一次都没走完。
  所以 `lin_replan_tol = 10 mm`：目标只小幅更新时**只更新终点，不重起状态机**。

### (f) 整段 moveL：`move_linear_to` / `start_axis_path` / `--lin-all`

`--lin-all`（`controller.linear_all`）把"① 路径层"从"关节空间最短路径的像"换成
**一组轴对齐的笛卡尔直线段**：所有绝对位置目标（`--pos`、6003 的 `pos`、交互命令 `p`）
都路由到 `ArmController.move_linear_to(arm, T_goal)`。

- `move_linear_to` → `start_axis_path`：用 `_axis_waypoints` 把"当前位置→目标"按 `axis_order`
  （默认 `AXIS_ORDER = ("z","y","x")`）拆成若干**轴对齐**路点（某轴位移 ≤ `AXIS_MIN_STEP`
  1mm 就不单独成段），再逐段建 `LinearMove` 放进 `self._queue[arm]`。
- **段与段之间"角点停一下"**：每个 `LinearMove` 的 S 形时间律末速精确为 0，所以段末天然停顿，
  下一段再从角点重新起速。`_advance_lin` 在段完成时弹出队首、把下一段设为当前段
  （`self.lin[arm] = queue[0]`）。姿态变化按段数均摊到各段。
- 几何/时间律/回退/失效处理全部复用 §2.4(a)(b)(d)：每段都仍是"位置直线 + 姿态测地线 +
  预计算 S 形曲线"，并沿用 `rollback()`（IK 失败/关节限速时不让路点跑在手臂前面）。
- **幂等**：正在走这条路径、且新终点没挪动（≤ `lin_replan_tol`）→ 只更新"到位判定的终点"；
  已站在目标上 → 不新起段；否则从当前指令位姿重新起一条轴分解路径。
- 与 `--lin-approach` 同开时 **`--lin-all` 优先**（启动会告警）。
- 为什么轴分解更稳：每段都短 → IK 是局部的、不会跨奇异点、肘部没机会翻分支；这也是
  "外部连续发小增量"看起来又直又稳的同一个道理（见 §1.1 的 PTP 弧与零空间讨论）。
- 代价：直线是几何直线、**不做避障**，可能穿过不可达区/奇异点——中途 IK 连续失败会按
  `--lin-abort-cycles` 取消**整条路径**（`cancel_linear` 会清空 `_queue`）并停住。

## 2.5 IK 层：约束非线性最小二乘（`g1_ik.py`）

### (a) 模型：14 维缩链 + 基座搬到 torso_link

- `G1ArmModel.__init__`（`g1_ik.py:167`）：加载完整 URDF → 用 `locked_joint_names()`
  **从 URDF 推导**要锁的关节（腿 12 + 腰 3 + 手/夹爪）→ `pin.buildReducedModel` →
  `nq = 14`（左右各 7，即每条臂是一个 7-DOF 冗余臂）。
- `_rebase_to_torso`（`g1_ik.py:255`）：把 reduced 模型基座从 pelvis **搬到 `torso_link`**——
  对所有 `parents[j] == 0` 的关节和 `parentJoint == 0` 的 frame 左乘 `inv(C_torso)`。
  于是 `fk() / ee_jacobians() / IK` 天然全部在躯干系里，**腰角完全不进入手臂几何**
  （已验证误差 ~1e-16）。这是本库相对上游宇树源码的主要改动之一。
- 末端 frame `L_ee`/`R_ee`：挂在 `wrist_yaw_joint` 上的 OP_FRAME，偏移 `(ee_offset, 0, 0)`。
  默认 `0.152`（Dex1 抓取中心），`0.185` = 指尖平面，Dex3 用 `0.05`。

### (b) 主求解器 `ArmIKCasadi`（默认 `--solver auto` → casadi）

```
minimize   50·‖e_pos‖² + 1.0·‖e_rot‖² + w_reg·‖q‖² + 0.1·‖q − q_ref‖²
subject to lowerPositionLimit ≤ q ≤ upperPositionLimit        (URDF 限位，硬约束)

e_pos = p_cur − p_target            (两条臂堆叠，6 维，单位 m)
e_rot = log3(R_cur · R_targetᵀ)     (两条臂堆叠，6 维，SO(3) 对数映射，单位 rad)
```

- 求解器：CasADi `Opti` + **IPOPT**，`max_iter=30, tol=1e-4, acceptable_tol=5e-4,
  warm_start_init_point=yes, jacobian_approximation=exact, calc_lam_p=False`。
- NLP 里的正解是**符号表达式**：优先 `pinocchio.casadi`（`cpin.framesForwardKinematics`
  + `cpin.log3`，= 上游宇树原路径）；PyPI 装不到时用内置 `SymbolicArmKinematics`
  （同一份 URDF 数据搭 CasADi 表达式，数值差 **2.22e-16**）。
- **热启动**：`set_initial(var_q, q_meas)` —— 用**本周期实测关节角**。
- **平滑参考**：`q_ref = q_meas`（`--ik-smooth-ref measured`，与上游一致）或 `q_last`。
- **失败兜底**：不收敛时 `last_ok=False`，返回 `opti.debug.value(var_q)`（发散迭代点）；
  **控制器拒绝使用它**，保持上一帧命令。

### (c) 冗余是怎么被处理的（重要）

14 个自由度对 12 维任务（2 臂 × 6）→ **2 维零空间，每条臂正好 1 维**（就是 7-DOF 的自运动）。

**本库不显式使用任何零空间目标函数**：没有可操作度最大化、没有限位距离最大化、
没有避障势场。零空间靠两项**软代价**锚定：

1. `0.1·‖q − q_ref‖²`（`w_smooth`，`q_ref` = 本周期实测角）→ 语义是"停在当前构型"；
2. `w_reg·‖q‖²`（正则项）——**默认被改成 0**。

为什么把 `w_reg` 从上游的 0.02 改成 0：上游正则项会让解主动用几毫米的位置误差去换
更小的正则代价，实测带来 **≈3 mm 系统性偏置**，而且静止保持时会缓慢朝零位漂移
（固定目标保持 2.4 s：`w_reg=0.02` 时肘关节漂移 0.2635 rad、末端残差 2.389 mm；
`w_reg=0` 时 0.0004 rad / 0.0007 mm）。详见 `docs/对照宇树源码.md §8`。

### (d) 回退求解器 `ArmIKDLS`（`g1_ik.py:803`）

无 CasADi/IPOPT 时使用，也可交叉验证。Levenberg–Marquardt：

```
dq = −Jᵀ (J Jᵀ + λ²I)⁻¹ e                       # 行权重重标定：sqrt([50,50,50,1,1,1]) 每臂
dq += (I − J⁺J) · 0.02 · (q_ref − q)            # 零空间弱牵引，抑制冗余漂移
‖dq‖ 限幅到 0.25 rad；λ 接受则 ×0.5、拒绝则 ×4（clamp [1e-4, 1]）
迭代 ≤ 30 次，收敛判据 pos < 1e-4 m 且 rot < 1e-3 rad
```

这里能看到经典的 **DLS + 梯度投影零空间牵引**结构——正是第一部分第 3、4 节的内容，
只不过它是"回退方案"而不是主方案。

| 3 | **冻结非受控臂** | — | `q_new[:7] = prev[:7]`（控右）或 `q_new[7:] = prev[7:]`。注意冻结到的是**上一帧指令**，不是实测。两臂链独立，所以这是精确的 |

### 笛卡尔钳制 `_clamp_ee_motion` 细节（`controller.py:891`）

用雅可比把关节增量映射成末端速度，再**整体缩放**：

```
J = model.ee_jacobians(q_prev)                  # 6×14，LOCAL_WORLD_ALIGNED
v_vec = J[:3] @ dq ;  w_vec = J[3:] @ dq
sp = ‖v_vec‖ ;  sw = ‖w_vec‖                    # 本周期末端位移量

线速度上限（三级）：
  v_cap = ee_speed                                        # ① 速度上限
  v_cap = min(v_cap, _ee_v + ee_accel·dt)                 # ② 加速度爬升
  v_cap = min(v_cap, sqrt(2·ee_accel·d_arm))              # ③ 临近目标提前减速（梯形）
  若 ee_jerk>0：把期望加速度按 ±ee_jerk·dt 限幅后再积分，得到 S 形速度曲线

角速度上限：同构（ee_rot_speed / ee_rot_accel / ee_rot_jerk）

全局缩放：scale = min(刻度, v_cap·dt/sp, w_cap·dt/sw)，clamp 到 [0,1]
返回 dq·scale
```

三个值得注意的工程细节（代码注释里都写了踩坑过程）：

- **到位臂不参与制动上限**：剩余距离 ≤ 1 µm 的臂若参与 `sqrt(2·a·d)`，
  会把**全局** `scale` 拉到 ~0，从而冻住另一条正在运动的臂（`--arm both` 实测完全不动）。
  所以剩余距离/角度按臂给、且加了 1 µm 门限。
- **加速度状态按"真正达成"回写**：`_ee_a[arm] = scale · a_used`。因为全局 `scale` 把增量
  压小之后实际加速度是 `scale·a`，若继续存期望值，下周期的 jerk 限制会以为已经爬得更高，
  起停首周期会失真。
- **量纲**：`sp = ‖J·dq‖` 是"本周期末端位移（m）"，`v_cap` 是"速度（m/s）"，所以比较要乘 `dt`。

**这一层的设计意图**（代码注释原话）："与 IK 用什么权重、什么求解器无关：设定值一定成立"。
也就是说 **速度/加速度/jerk 的保证来自这一层，而不是来自 IK**。

---

## 2.7 安全门与失效处理（`controller.py:step()` 前半段）

按顺序，任何一条不满足就**本周期不下发**（不是停下来，是保持上一帧）：

1. 状态帧为 None → `尚无状态帧`；
2. `q14` 或腰角含 NaN/Inf → 显式拦下（注释说明 `np.clip(nan) == nan`，NaN 会一路发到 6002）；
3. 状态帧年龄 > `--state-timeout`（默认 0.25 s）→ `状态超时`；
4. 目标位姿含 NaN/Inf → `_assign_target` 直接抛错拒绝；
5. IK 异常 / 返回 None / 非有限 / `last_ok == False` → **保持上一帧命令**
   （注释解释了为什么不能照着 `opti.debug` 的发散点走：会每周期 2° 地朝一个错误构型爬）；
6. LIN 段：IK 失败 → `rollback()` 回退路点；连续失败 ≥ `--lin-abort-cycles`（默认 5）→
   **取消整段**，让手臂停下来而不是硬着头皮往盒子里推；
7. `--require-vla`：机器人不在 VLA 模式 → `set_send_enabled(False)`；
   恢复时自动 `reanchor()`——清掉 `q_cmd` / IK 热启动 / 滤波器 / 末端速度加速度记忆，
   下一帧走"首帧初始化"路径，从**实测位姿**平滑起步（避免恢复瞬间把手臂拽回旧指令）。

## 2.8 到位判定（`arrival.py`）—— 停止条件，不是规划

6 个门 AND，全部满足并连续保持 `--arrive-dwell`（0.2 s）才算到位：

| 门 | 参数 | 默认 |
|---|---|---|
| 实测位置/姿态残差 | `--arrive-pos` / `--arrive-rot` | 2 mm / 1° |
| **反解**位置/姿态残差（可达性） | `--arrive-ik-pos` / `--arrive-ik-rot` | 3 mm / 2°（0=不判） |
| 末端速度 EMA | `--arrive-speed` | 15 mm/s |
| 关节速度 EMA | `--arrive-joint-speed` | 10°/s |
| 状态帧新鲜 + 本帧确实下发 | `--state-timeout` 内 | — |
| 该臂确实被驱动 | `info.controlled` | — |

带**滞回**（离开阈值 = 到位阈值 × 2）和**原因分类**（`✗跟随中` / `✗不可达` / `✗疑似被挡` /
`✗状态失联` / `✗未被驱动`）。原因分类只在"手臂确实停下来了"（末端速度 < 1 mm/s 且距目标变更
> 2×dwell + 0.1 s）之后才下"不可达/被挡"的**稳态**结论——避免在限速追赶过程中误报。
判定本身**不改变任何控制行为**；`--on-arrive freeze|exit` 与夹爪动作挂在它的事件上。

## 2.9 实测性能（`docs/协议与实测.md`）

| 项目 | 结果 |
|---|---|
| IPOPT 单帧（50 Hz、目标平滑移动） | 首帧 12.3 ms，之后 mean **5.3 ms** / max 12.3 ms |
| IPOPT 单帧（目标大幅跳变、零位冷启动） | 30~40 ms（`max_iter=30` 跑满）→ **会超一个 20 ms 周期** |
| 闭环残差（`--w-reg 0`） | `ik_err` **0.1 mm / 0.0°**，`track_err` 0.3 mm |

| 静态目标单臂到位耗时 | casadi **1.72 s**；dls 1.29 s |
| 轨迹跟踪（`--demo circle` r=5cm） | 5 s 内 **0 次**误判到位（速度判据拦住了"路过式到位"） |
| 不可达目标 | 如实报 `✗不可达`，手臂停在能到的最近处 |

## 2.10 与本库设计对照的方法学小结

| 维度 | 本库的选择 | 调研里的其它选项 | 差距/风险 |
|---|---|---|---|
| ① 路径层 | 默认**无显式路径**（关节空间最短路径的像）；`--lin-all` 走 Z→Y→X 轴分解直线段；`--lin-approach` 的 LIN 段是沿工具轴直线 | 笛卡尔样条/圆弧；采样规划出的关节空间折线 | 默认模式末端走**弧**，弧的形状取决于 IK 分支，可能撞中间障碍物 |
| ② 时间律层 | LIN 段：**预计算网格 + 对称 S 形/梯形**（速度/加速度/jerk 三限幅，镜像减速） | TOPP/TOPP-RA（非对称限幅、任意路径、全局时间最优）；最小 jerk 五次多项式 | 对称镜像只对"起止速度都为 0"的一段最优；PTP 段完全没有显式时间律 |
| ③ 伺服层 | **每周期整段全位姿 NLP 反解**（IPOPT，硬限位约束）+ 雅可比笛卡尔钳制 | resolved-rate / DLS / RAC 速率环；QP+HQP 带限位不等式 | 单帧 5.3 ms（跳变 30~40 ms）在 50 Hz 下余量不大；无 RAC/力矩层 |
| 冗余（7-DOF 的 1 维零空间） | 只用**软代价** `0.1‖q−q_ref‖²` 锚定（"停在当前构型"）；`w_reg=0` | 可操作度最大化、限位距离最大化、避障势场、臂角参数化、零空间梯度投影、HQP | **没有**奇异回避、**没有**肘部避障、**没有**分支保证 |
| IK 分支连续性 | 热启动（实测角）+ 平滑代价项 | 显式分支检查选最近解；臂角参数化（唯一有保证的） | 属于**统计性**保证，不是硬保证；理论上有肘部翻转可能 |
| 奇异处理 | IPOPT 硬限位 + DLS 的阻尼 λ | DLS/SRI 阻尼、可操作度目标、规划上绕开 | 没有可操作度监控，没有奇异预警 |
| 避障 | **完全没有**（`pre-grasp` 要靠人工确认落在自由空间） | CHOMP/TrajOpt/GPMP2/OMPL+MoveIt | 最大的功能缺口；抓取场景靠"目标点人工验证 + 工具轴直线"规避 |
| 全局规划 | 无 | RRT*/PRM/OMPL | 只有局部方法，没有"找不到解就换条路"的能力 |
| 到位/停止 | 6 门 AND + 滞回 + 驻留 + 原因分类 | 一般只需位姿误差判据 | 这一层比多数实现更完善 |
| 失效处理 | IK 失败保持上一帧；LIN 失败回退路点、超阈值取消整段；状态超时不下发 | 多数实现只做限幅 | 这一层也比多数实现更完善 |
| 确定性/可测性 | LIN 段预先规划 → 可离线单测（7 项）；有 `audit_motion_path.py` 量直线度 | 逐拍反馈跟踪式实现难以离线复现 | 工程可验证性明显强于"边跑边算"的做法 |
